# 帖子/评论头像字段 — 后端改动思路与实现记录

## 改动时间
2026-06-24

## 改动目标
帖子列表、帖子详情、评论列表的每个帖子/评论都能展示**作者名字**和**作者头像**。

- 匿名帖子：`authorName = "匿名用户"`，`authorAvatar = null`
- 实名帖子：`authorName = nickname`（没有就用 `username`），`authorAvatar = user.avatar`
- 评论：同上实名逻辑

## 三、SQL 查询改动

### 3.1 `PostMapper.xml` — `selectByPage`（帖子分页列表）

**改动前**：只查 `post` 表，不返回 `authorName` 和 `commentCount`

```sql
select id, user_id, title, content, type, is_anonymous, like_count, create_time
from post
```

**改动后**：LEFT JOIN `user` 表，用 `CASE WHEN` 区分匿名/实名：

```sql
SELECT p.id, p.title, p.content, p.type, p.is_anonymous, p.like_count, p.create_time,
       CASE WHEN p.is_anonymous = 1 THEN '匿名用户'
            ELSE COALESCE(u.nickname, u.username)
       END AS authorName,
       CASE WHEN p.is_anonymous = 1 THEN NULL
            ELSE u.avatar
       END AS authorAvatar,
       (SELECT COUNT(*) FROM comment c WHERE c.post_id = p.id) AS commentCount
FROM post p
LEFT JOIN user u ON p.user_id = u.id
ORDER BY p.create_time DESC
```

**核心逻辑**：
- `COALESCE(u.nickname, u.username)`：优先取昵称，昵称为 NULL 时回退到用户名
- 匿名时 `authorAvatar` 直接返回 `NULL`
- 子查询计算评论数

### 3.2 `PostMapper.xml` — `searchPosts`（搜索）

改动同上，在原来只取 `u.nickname` 的基础上：
- 加 `authorAvatar` 字段
- `authorName` 改用 `COALESCE(u.nickname, u.username)` 兜底

### 3.3 `CommentMapper.xml` — `selectCommentsByPostId`（评论列表）

**改动前**：
```sql
SELECT c.id, c.post_id, c.content, c.create_time,
       u.nickname AS authorName
FROM comment c
LEFT JOIN user u ON c.user_id = u.id
```

**改动后**：
```sql
SELECT c.id, c.post_id, c.content, c.create_time,
       COALESCE(u.nickname, u.username) AS authorName,
       u.avatar AS authorAvatar
FROM comment c
LEFT JOIN user u ON c.user_id = u.id
```

### 4.2 `PostServiceImpl.java` — `getPostDetail()`

**改动前**：
```java
// 处理作者名称
if (post.getIsAnonymous() != null && post.getIsAnonymous() == 1) {
    detailVO.setAuthorName("匿名用户");
} else {
    String nickname = postMapper.selectNicknameByUserId(post.getUserId());
    detailVO.setAuthorName(nickname != null ? nickname : "未知用户");
}
```

**改动后**：
```java
// 处理作者名称和头像
if (post.getIsAnonymous() != null && post.getIsAnonymous() == 1) {
    detailVO.setAuthorName("匿名用户");
    detailVO.setAuthorAvatar(null);
} else {
    String nickname = postMapper.selectNicknameByUserId(post.getUserId());
    String username = postMapper.selectUsernameByUserId(post.getUserId());
    String avatar = postMapper.selectAvatarByUserId(post.getUserId());
    // 优先使用昵称，没有则使用用户名
    detailVO.setAuthorName(nickname != null && !nickname.isEmpty() ? nickname : username);
    detailVO.setAuthorAvatar(avatar);
}
```

> 评论的组装在 `CommentMapper.xml` 的 SQL 层就完成了（`LEFT JOIN user`），Service 层不用额外处理。

## 八、联表查询（JOIN）从零到会用

> 这一节专门写给联表查询不熟的同学，用本项目真实的表结构当例子。

### 8.1 先搞懂：为什么需要联表查询？

你的数据库里有多张表，数据是**分开存的**：

```
┌─────────────────────┐        ┌──────────────────────┐
│       post 表        │        │       user 表         │
├─────────────────────┤        ├──────────────────────┤
│ id          (帖子ID) │        │ id           (用户ID) │
│ user_id    (发帖人)  │ ───→   │ username    (用户名)  │
│ title        (标题)  │        │ nickname    (昵称)    │
│ content      (内容)  │        │ avatar      (头像URL) │
│ is_anonymous(是否匿名)│       │ role         (角色)    │
│ like_count (点赞数)  │        └──────────────────────┘
│ create_time (时间)   │
└─────────────────────┘
```

`post` 表里只存了 `user_id`（一个数字），没有存用户名、头像。前端要展示"小王 · 头像图片"，你必须拿着这个 `user_id` 去 `user` 表把对应的那一行找出来。

**两种做法：**

| 做法 | 方式 | 优缺点 |
|------|------|--------|
| Java 代码里查两次 | 先查 post，拿到 user_id，再查 user | 两次数据库请求，慢 |
| SQL 联表查询 | 一条 SQL 把两张表的数据一起查出来 | 一次请求，快 |

本项目全部用 SQL 联表查询。

### 8.2 核心概念：LEFT JOIN 到底干了什么？

假设现在有两张表：

**post 表（帖子）**：
| id | user_id | title |
|----|---------|-------|
| 1 | 4 | 吐槽食堂 |
| 2 | 5 | 建议增加自习室 |
| 3 | NULL | 匿名吐槽（user_id为空） |

**user 表（用户）**：
| id | nickname | avatar |
|----|----------|--------|
| 4 | 小王 | wang.jpg |
| 6 | 小李 | li.jpg |

#### INNER JOIN（内连接）

```sql
SELECT p.title, u.nickname
FROM post p
INNER JOIN user u ON p.user_id = u.id
```

**结果：只保留"两边都能匹配上"的行**

| title | nickname |
|-------|----------|
| 吐槽食堂 | 小王 |

只有帖子1匹配上了（user_id=4 在 user 表里存在）。
- 帖子2被丢弃（user_id=5，但 user 表里没有 id=5 的用户）
- 帖子3被丢弃（user_id=NULL，没得匹配）

> **记忆口诀："两边都有才留下"**

#### LEFT JOIN（左连接）

```sql
SELECT p.title, u.nickname
FROM post p
LEFT JOIN user u ON p.user_id = u.id
```

**结果：左边（post）全部保留，右边（user）能匹配就填，匹配不上填 NULL**

| title | nickname |
|-------|----------|
| 吐槽食堂 | 小王 |
| 建议增加自习室 | NULL |
| 匿名吐槽（user_id为空） | NULL |

> **记忆口诀："左边的表是老大，全都要；右边的表来帮忙，能帮就帮，帮不了拉倒"**

#### 什么时候用哪个？

| 场景 | 用什么 | 原因 |
|------|--------|------|
| 查帖子+作者信息 | **LEFT JOIN** | 帖子的 user_id 可能为空（匿名），即使 user 被删了帖子也要展示 |
| 查订单+商品 | INNER JOIN | 订单必须有商品，没有商品的订单是脏数据 |
| 查评论+用户 | **LEFT JOIN** | 用户被删了评论也应该保留（显示"已注销用户"） |

**本项目全部用 LEFT JOIN，原因就是上面说的：数据不完整时也不能丢。**

### 8.3 表别名 — `post p` 和 `user u` 是什么意思？

```sql
FROM post p
LEFT JOIN user u ON p.user_id = u.id
```

`p` 和 `u` 是**别名（alias）**，相当于给表起了个小名，之后整个 SQL 里都用小名来引用。

```sql
-- 不用别名：写起来很长
SELECT post.title, user.nickname
FROM post
LEFT JOIN user ON post.user_id = user.id

-- 用别名：简洁清晰
SELECT p.title, u.nickname
FROM post p
LEFT JOIN user u ON p.user_id = u.id
```

> **约定**：通常取表名的首字母做别名。`post → p`，`user → u`，`comment → c`。

### 8.4 实战分解：本项目最复杂的一条联表 SQL

以 `selectByPage`（帖子分页列表）为例，逐行拆解：

```sql
 1  SELECT
 2      p.id,                                     -- post表自己的字段
 3      p.title,
 4      p.content,
 5      p.type,
 6      p.is_anonymous,
 7      p.like_count,
 8      p.create_time,
 9
10      CASE WHEN p.is_anonymous = 1               -- 匿名判断
11          THEN '匿名用户'
12          ELSE COALESCE(u.nickname, u.username)   -- 联表查到的user字段
13      END AS authorName,
14
15      CASE WHEN p.is_anonymous = 1                -- 匿名判断
16          THEN NULL
17          ELSE u.avatar                            -- 联表查到的头像
18      END AS authorAvatar,
19
20      (SELECT COUNT(*)                            -- 子查询算评论数
21       FROM comment c
22       WHERE c.post_id = p.id) AS commentCount
23
24  FROM post p                                     -- 主表（左边）
25  LEFT JOIN user u ON p.user_id = u.id            -- 关联user表（右边），条件：post的user_id = user的id
26  ORDER BY p.create_time DESC                     -- 按时间倒序
```

**执行过程（用脑子跑一遍）：**

1. 数据库从 `post` 表拿出一行（比如 id=5，user_id=4）
2. `LEFT JOIN user u ON p.user_id = u.id` → 去 `user` 表找 `id=4` 那一行
3. 找到了！user 表那一行是：id=4, nickname='小王', avatar='wang.jpg'
4. 第12行 `COALESCE(u.nickname, u.username)` → '小王'
5. 第17行 `u.avatar` → 'wang.jpg'
6. 第10行 `p.is_anonymous = 1`？→ 不是（=0），所以走 ELSE
7. `authorName` = '小王'，`authorAvatar` = 'wang.jpg'
8. 下一行 post…重复

### 8.5 三个关键函数的白话解释

#### `COALESCE(a, b)` — 备胎函数

```sql
COALESCE(u.nickname, u.username)
```

翻译成人话：**先用 nickname，如果 nickname 是 NULL，就用 username。**

```sql
COALESCE(NULL, '小王')   → '小王'    （第一个是NULL，用第二个）
COALESCE('小明', '小王') → '小明'    （第一个有值，直接用）
COALESCE(NULL, NULL)    → NULL      （都是NULL，没办法了）
```

> 可以传多个参数：`COALESCE(a, b, c, d)` → 从左边开始，返回第一个不是 NULL 的值。

#### `CASE WHEN` — 条件判断

```sql
CASE WHEN p.is_anonymous = 1 THEN '匿名用户'
     ELSE COALESCE(u.nickname, u.username)
END AS authorName
```

翻译成人话：**如果帖子是匿名的，名字填"匿名用户"；否则去 user 表取昵称。**

```sql
-- 等同于 Java 里的：
if (post.isAnonymous == 1) {
    authorName = "匿名用户";
} else {
    authorName = user.nickname != null ? user.nickname : user.username;
}
```

#### 子查询 — SELECT 里面套 SELECT

```sql
(SELECT COUNT(*) FROM comment c WHERE c.post_id = p.id) AS commentCount
```

翻译成人话：**去 comment 表数一下，有多少条评论的 post_id 等于当前这个帖子的 id。**

```
对 post id=5 来说：
  去 comment 表执行 SELECT COUNT(*) FROM comment WHERE post_id = 5
  得到 3 → commentCount = 3
```

### 8.6 本项目三张表的关联关系图

```
        post 表                     user 表
    ┌──────────────┐           ┌──────────────┐
    │ id           │           │ id           │
    │ user_id ─────┼──LEFT JOIN→│ nickname     │
    │ title        │           │ username     │
    │ content      │           │ avatar       │
    │ is_anonymous │           └──────────────┘
    │ like_count   │
    └──────┬───────┘
           │
           │ 一个帖子有多条评论
           │ (post.id = comment.post_id)
           │
    ┌──────┴───────┐           ┌──────────────┐
    │ comment 表    │           │ user 表       │
    │ id           │           │ id           │
    │ post_id ─────┘  LEFT JOIN│ nickname     │
    │ user_id ────────→        │ username     │
    │ content      │           │ avatar       │
    └──────────────┘           └──────────────┘
```

**箭头方向就是 ON 条件的方向：**
- `post.user_id = user.id`（帖子的发帖人ID → 用户表找用户）
- `comment.post_id = post.id`（评论的所属帖子ID → 帖子表）
- `comment.user_id = user.id`（评论的评论人ID → 用户表找用户）

### 8.7 常见错误排查

**错误1：查出来的 authorName 全是 NULL**
```sql
-- 错误写法：JOIN 条件写错了
LEFT JOIN user u ON p.id = u.id   -- ❌ 用 p.id（帖子ID）去匹配 u.id（用户ID），牛头不对马嘴
-- 正确写法：
LEFT JOIN user u ON p.user_id = u.id  -- ✅ 用 p.user_id（发帖人ID）匹配 u.id（用户ID）
```

**错误2：不需要的字段也联表查**
```sql
-- 不好：密码也查出来了
SELECT p.*, u.password   -- ❌ 密码绝对不该返回给前端！
-- 好：
SELECT p.id, p.title, u.nickname, u.avatar  -- ✅ 只查需要的字段
```

**错误3：忘记用表别名区分同名字段**
```sql
-- 错误：两张表都有 id 字段，数据库不知道你要哪个
SELECT id, title, nickname FROM post LEFT JOIN user ON ...
-- 正确：
SELECT p.id, p.title, u.nickname FROM post p LEFT JOIN user u ON ...
```

**错误4：用 INNER JOIN 导致部分数据消失**
```sql
-- 不好：user_id 为 NULL 的帖子直接消失
FROM post p INNER JOIN user u ON p.user_id = u.id
-- 好：所有帖子都保留
FROM post p LEFT JOIN user u ON p.user_id = u.id
```

### 8.8 总结：写联表查询的步骤

1. **想清楚主表是谁**（你要查什么？帖子列表 → post 是主表）
2. **主表放 FROM 后面，给个别名**
3. **想清楚要关联哪张表、用什么条件**（需要用户信息？→ LEFT JOIN user ON 主表.user_id = user.id）
4. **SELECT 里用 `表别名.字段` 取数据**
5. **用 COALESCE / CASE WHEN 处理特殊情况**（匿名、字段为NULL）

> **一句话：联表查询就是把"Java里查两次"变成了"SQL里一次查完"。LEFT JOIN 保证左边表的数据一条不丢，右边能匹配就填，匹配不上就 NULL。**
