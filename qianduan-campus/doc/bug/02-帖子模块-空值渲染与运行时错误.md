# 帖子模块空值渲染与运行时错误

## 问题现象

控制台出现过以下问题：

1. `authorName.charAt(0)` 报错
2. 帖子类型相关的组件 API 警告
3. 帖子筛选项出现 `ElOption value` 类型问题

## 根因分析

### 1. 作者名为空导致运行时错误

原来部分页面直接写了：

```vue
post.authorName.charAt(0)
```

如果后端返回 `authorName = null`，就会报：

```text
Cannot read properties of null (reading 'charAt')
```

### 2. `el-radio` 使用了旧写法

原来发布帖子页写法类似：

```vue
<el-radio :label="0">吐槽</el-radio>
```

Element Plus 新版本会警告：

```text
label act as value is about to be deprecated
```

因为推荐写法已经变成 `:value="0"`。

### 3. 筛选项中使用了 `null`

帖子列表页原来有：

```vue
<el-option label="全部" :value="null" />
```

这会触发和资源页一样的 `ElOption value` 类型警告。

## 已处理思路

- 作者名统一加兜底逻辑，例如空值时显示“匿名用户”
- `el-radio` 改用 `value`
- 筛选“全部”从 `null` 改成空字符串

## 结论

这类问题的共同本质是：

- 前端对异步返回数据的空值保护不足
- 组件库 API 用法没有完全跟上当前版本
