# 帖子发布匿名/实名显示异常

## 问题现象

发布帖子时，无论在发布页选择“实名发布”还是“匿名发布”，帖子列表和帖子详情里都表现为匿名。

具体表现为：

1. 用户在发布页切换匿名开关后，展示结果没有明显区别
2. 列表页和详情页中，作者名称容易一直显示为“匿名用户”
3. 排查时难以判断到底是前端展示误判，还是后端真实返回了匿名数据

## 根因分析

这次问题实际拆开后有两层：

### 1. 发布请求需要更明确地传递 `isAnonymous`

发布页虽然使用了 `el-switch`，并配置了：

```vue
:active-value="1"
:inactive-value="0"
```

但为了避免提交时出现值类型不明确的问题，前端在提交时应显式组装请求体，并将：

```js
isAnonymous: Number(form.isAnonymous)
```

明确传给后端。

### 2. 前端原有作者名兜底逻辑会掩盖真实问题

原来的帖子列表页和详情页都存在类似写法：

```js
return name || '匿名用户'
```

这会带来一个副作用：

- 只要后端返回的 `authorName` 为空
- 前端就直接显示成“匿名用户”

这样即使帖子其实是实名发布，只要后端没有正确返回作者名，前端看起来也像“匿名发布”，从而把“作者名缺失”和“匿名发布”混在了一起。

## 修复思路

本次修复分成两部分：

1. 发布帖子时，显式构造请求对象并传递数字类型的 `isAnonymous`
2. 列表页与详情页统一按 `isAnonymous === 1` 判断是否显示“匿名用户”
3. 对实名但作者名缺失的情况，改为显示“未知用户”，避免误判成匿名

## 修复后的判断方式

修复后可以更清晰地区分问题来源：

1. 如果帖子带有“匿名”标签，说明后端返回的 `isAnonymous` 为 `1`
2. 如果帖子没有“匿名”标签，但作者显示“未知用户”，说明后端没有正确返回实名作者名
3. 如果帖子没有“匿名”标签，且作者名正常显示，说明匿名/实名链路正常

## 验证结果

本次修复后已完成前端构建验证：

```bash
npm run build
```

构建通过，说明本次修改未引入前端编译错误。

## 结论

这个问题的关键不是单纯“开关写反了”，而是：

- 发布参数需要更明确地传递
- 展示层不能把“作者名为空”直接等同于“匿名发布”

把这两层拆开后，前后端联调时就能更准确地定位到底是匿名状态异常，还是作者名回传异常。
