# 个人博客前端改造文档

## 一、文档说明

### 1.1 基本信息

| 项目 | 说明 |
|------|------|
| 所属项目 | `qianduan-campus` |
| 改造目标 | 在尽量不动后端接口和数据库的前提下，把校园社区前端包装为个人博客 |
| 技术栈 | Vue 3 + Element Plus + Vite |
| 方案定位 | 最省事方案 |
| 文档版本 | v1.0 |
| 创建日期 | 2026-06-27 |

### 1.2 核心思路

本方案不追求一次性做成完整博客系统，而是优先完成以下目标：

1. 保留现有登录、用户、帖子、评论、资料、工具箱能力
2. 把“帖子”在前端展示层重命名为“文章”
3. 把“校园社区”的文案、入口、页面结构改成“个人博客”
4. 尽量不新增接口，不改动现有请求路径

### 1.3 改造原则

- 不改 `src/api/post.js` 的请求路径
- 不改帖子详情、列表、搜索、评论的基本交互链路
- 不动数据库字段时，前端不要依赖“分类、标签、封面、摘要”等新字段
- 所有博客语义优先通过前端文案和布局调整实现

- 不新增文章封面字段

## 四、路由与导航改造

### 4.1 推荐保留现有路径

为了最省事，首版建议保留原路径不动，只改标题和文案：

| 现有路径 | 页面用途 | 前端展示名称 |
|------|------|------|
| `/home` | 首页 | 首页 |
| `/post/list` | 帖子列表 | 文章 |
| `/post/detail/:id` | 帖子详情 | 文章详情 |
| `/post/publish` | 发帖 | 写文章 |
| `/resource` | 学习资料 | 资源 |
| `/toolbox` | 小工具箱 | 工具 |
| `/profile` | 个人中心 | 我的 |
| `/admin/dashboard` | 后台管理 | 后台 |

这样做的好处：

- 不用改已有跳转逻辑太多
- 不用担心和后端接口命名割裂
- 首版上线最快

### 4.2 `src/router/index.js` 改造建议

建议只改 `meta.title` 文案，不改路径：

| 原标题 | 建议标题 |
|------|------|
| 首页 | 首页 |
| 校园墙/讨论区 | 文章 |
| 帖子详情 | 文章详情 |
| 发布帖子 | 写文章 |
| 学习资料 | 资源 |
| 小工具箱 | 工具 |
| 个人中心 | 我的 |
| 后台管理 | 后台管理 |

### 4.3 `Layout.vue` 侧边栏菜单建议

首版建议菜单改成：

1. 首页
2. 文章
3. 资源
4. 工具

6. 后台管理（仅管理员）

不建议首版就上“分类 / 标签 / 项目 / 归档”这些独立菜单，因为对应后端能力还没有。

4. 页面标题映射

- `/post/publish` 显示 `写文章`

5. 页脚文案

## 5.2 首页

文件：

```text
src/views/Home.vue
```

### 改造目标

把“社区欢迎页 + 热门帖子”改成“博客首页 + 最新文章”。

### 当前问题

当前首页存在明显社区语义：

- 欢迎来到网站频道
- 发表聊天帖子
- 浏览帖子
- 热门帖子
- 吐槽/建议标签

### 建议改法

#### 方案一：最省事方案

仅改文案和卡片标题，不大改数据结构。

首页区块改为：

1. 顶部欢迎区
2. 最新文章列表

#### 顶部欢迎区建议

- 标题改为：`欢迎来到我的个人博客`
- 副标题改为：`这里记录开发、学习和生活里的想法。`

快捷按钮建议改成：

| 当前按钮 | 建议按钮 |
|------|------|
| 发表聊天帖子 | 写文章 |
| 浏览帖子 | 查看文章 |
| 学习资料 | 资源分享 |
| 小工具箱 | 常用工具 |

#### 文章列表区建议

- `热门帖子` 改成 `最新文章`
- `查看更多` 改成 `查看更多文章`
- 不再显示 `吐槽 / 建议` 标签
- 卡片摘要继续使用 `title + content` 截断

### 数据层建议

保留现有：

```javascript
postAPI.getPostList({ page: 1, size: 10 })
```

只是把返回结果 `hotPosts` 改名为更符合博客语义的变量，例如：

```javascript
const latestArticles = ref([])
```

### 首页首版不建议新增的功能

- 分类导航
- 标签云
- 文章封面瀑布流
- 阅读量统计

这些都适合第二阶段再做。

## 5.5 写文章页

文件：

```text
src/views/Post/PostPublish.vue
```

### 改造目标

把“发布帖子页”改成“写文章页”。

### 最省事改法

不改接口，只改前端表单展示和提交值。

### 必改项

1. 标题文案

- `发布帖子` 改为 `写文章`

2. 去掉社区字段展示

首版建议在前端隐藏：

- 帖子类型 `type`
- 是否匿名 `isAnonymous`

3. 提交时固定传值

建议提交时固定：

```javascript
{
  title: form.title,
  content: form.content,
  type: 1,
  isAnonymous: 0
}
```

说明：

- `type: 1` 只是为了兼容后端必填字段
- `isAnonymous: 0` 表示博客文章统一实名

4. 表单字段保留最小集合

- 文章标题
- 文章内容

### 首版不建议做

- 封面上传
- Markdown 编辑器
- 草稿箱
- 分类标签选择

这些会明显带来后端和表结构改动。

## 八、最小执行顺序

建议按下面顺序改，最快出效果：

1. 改 `Layout.vue` 的站名、菜单、标题、页脚
2. 改 `Home.vue` 的欢迎文案和“热门帖子”区块
3. 改 `PostList.vue`，隐藏 `type` 和 `匿名` 展示
4. 改 `PostDetail.vue`，隐藏社区标签
5. 改 `PostPublish.vue`，固定提交 `type=1`、`isAnonymous=0`
6. 改 `ResourceList.vue` 和 `ToolboxHome.vue` 的文案
7. 最后统一检查路由标题

## 九、验收标准

完成后应满足以下结果：

1. 用户进入站点后，整体感知是“个人博客”而不是“校园论坛”
2. 首页展示最新文章，而不是聊天帖子
3. 用户可以继续发文、看文、评论、点赞
4. 前端仍然兼容现有 `/api/post/*`、`/api/comment/*`、`/api/resource/*`
5. 不依赖后端新增字段也能正常运行

## 十一、结论

这个项目改成个人博客，前端最省事的方案不是“重做一套博客系统”，而是：

- 保留现有帖子模块
- 在前端把它重新包装成文章系统
- 把社区化文案、筛选项、匿名逻辑隐藏掉
- 用最小代价先做出博客形态

这个方案的优点是：

- 改动集中
- 不依赖后端大重构
- 上线最快
- 后续还能平滑升级成更完整的博客系统
