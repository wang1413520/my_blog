# 我的资源前端开发文档

## 一、文档说明
### 1.1 基本信息

| 项目 | 说明 |
|------|------|
| 所属项目 | 校园墙前端（`qianduan-campus`） |
| 模块名称 | 个人中心 - 我的资源 |
| 技术栈 | Vue 3 + Element Plus + Vite |
| 关联页面 | `src/views/Profile.vue` |
| 复用模块 | `src/views/Resource/ResourceList.vue`、`src/api/resource.js` |
| 对接后端 | `GET /api/resource/my/list` |
| 文档版本 | v1.0 |
| 创建日期 | 2026-06-27 |

### 1.2 开发目标

在现有“个人信息 / 修改密码 / 我的资料”基础上，新增一个“我的资源”功能入口，用于展示当前登录用户上传到网站的学习资料。

本次前端改造目标：

- 不影响现有个人中心功能
- 左侧菜单新增“我的资源”
- 右侧展示当前用户上传的资料列表
- 支持关键字、文件类型、上传类型筛选
- 支持单文件和文件夹上传资料的统一展示
- 支持下载、删除、打开文件夹等操作

## 三、功能定位
### 3.1 和公共资源页的区别

公共资源页 `ResourceList.vue` 面向所有用户，展示站内全部资料。

“我的资源”页只展示：

- 当前登录用户自己上传的资料
- 包含单文件上传
- 包含文件夹上传中的每一个文件

### 3.2 页面能力范围

首版建议支持：

1. 查询我的资源列表
2. 关键字搜索
3. 文件类型筛选
4. 上传类型筛选
5. 下载资源
6. 删除资源
7. 文件夹上传资料分组展示
8. 查看文件夹内文件树

首版不强制支持：

- 资源编辑
- 批量删除
- 批量下载
- 重新上传覆盖

## 四、交互设计
### 4.1 用户流程

1. 用户进入“我的”页面
2. 点击左侧菜单“我的资源”
3. 前端调用后端接口加载当前用户上传的资源列表
4. 用户可按关键字、文件类型、上传类型筛选
5. 用户可下载或删除某个资源
6. 若资源来自文件夹上传，则支持展开查看目录

### 4.2 页面布局建议

右侧内容区建议结构：

```text
标题：我的资源
筛选区：关键字 + 文件类型 + 上传类型 + 搜索 + 重置
列表区：资源卡片 / 文件夹分组卡片
分页区
```

建议保留和公共资源页接近的视觉风格，降低认知成本。

## 六、接口对接设计
### 6.1 查询我的资源列表

- 请求方式：`GET`
- 请求路径：`/api/resource/my/list`
- 是否需要登录：是

请求参数建议：

| 参数名 | 类型 | 必填 | 说明 |
|------|------|------|------|
| page | number | 否 | 页码，默认 1 |
| size | number | 否 | 每页大小，默认 10 |
| keyword | string | 否 | 关键字，匹配标题/描述 |
| fileType | string | 否 | 文件类型：`pdf/doc/docx` |
| uploadType | string | 否 | 上传类型：`single/folder` |

前端调用示例：

```javascript
const params = {
  page: myResourceCurrentPage.value,
  size: myResourcePageSize.value
}

if (myResourceSearchForm.keyword) {
  params.keyword = myResourceSearchForm.keyword
}

if (myResourceSearchForm.fileType) {
  params.fileType = myResourceSearchForm.fileType
}

if (myResourceSearchForm.uploadType) {
  params.uploadType = myResourceSearchForm.uploadType
}

const data = await resourceAPI.getMyResourceList(params)
```

### 6.2 删除资源

直接复用现有接口：

- 请求方式：`DELETE`
- 请求路径：`/api/resource/{id}`

说明：

- 后端本身就应限制“仅上传者或管理员可删除”
- 因为“我的资源”页展示的本就是当前用户上传的资源，所以可以直接复用删除逻辑

### 6.3 下载资源

直接复用现有方法：

```javascript
resourceAPI.downloadResource(id)
```

## 十、核心逻辑建议
### 10.1 首次进入时加载

```javascript
const loadMyResourceList = async () => {
  myResourceLoading.value = true
  try {
    const data = await resourceAPI.getMyResourceList({
      page: myResourceCurrentPage.value,
      size: myResourcePageSize.value,
      keyword: myResourceSearchForm.keyword || undefined,
      fileType: myResourceSearchForm.fileType || undefined,
      uploadType: myResourceSearchForm.uploadType || undefined
    })

    myResourceList.value = data.records || []
    myResourceTotal.value = data.total || 0
    myResourceLoaded.value = true
  } finally {
    myResourceLoading.value = false
  }
}
```

### 10.2 菜单切换时懒加载

```javascript
const handleMenuSelect = async (index) => {
  activeMenu.value = index

  if (index === 'resources' && !myResourceLoaded.value) {
    await loadMyResourceList()
  }
}
```

### 10.3 删除后刷新

```javascript
const handleDeleteMyResource = async (id) => {
  await resourceAPI.deleteResource(id)
  ElMessage.success('删除成功')
  await loadMyResourceList()
}
```

## 十三、联调约束
### 13.1 登录限制

“我的资源”必须依赖登录状态，因此：

- 未登录不应展示该菜单或进入后应提示登录
- 接口必须校验当前登录用户

### 13.2 成功状态

由于当前项目 `src/utils/request.js` 中只接受 `code === 200`，因此后端必须保证：

- 查询成功：`code = 200`
- 空列表成功：`code = 200`
- 删除成功：`code = 200`
