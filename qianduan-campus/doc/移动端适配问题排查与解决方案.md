### 1. 首页主区域使用了偏桌面端的最小宽度网格

风险位置：

- `Home.vue:234-270` 附近的 `welcome-grid`、`welcome-top`、`welcome-feature`
- 已存在的断点只在 `900px` 做了一次纵向堆叠，但对 360px 到 430px 的手机宽度还不够细

解决方案：

1. 把首页断点从“只有一个 `900px`”改成至少三档：
   - `<= 900px`：整体改为单列
   - `<= 768px`：卡片间距、padding、字号进一步缩小
   - `<= 480px`：组件内部彻底改为竖排，去掉所有依赖横向并排的结构
2. `welcome-grid` 不要再依赖 `minmax(560px, ...)` 这种桌面最小宽度思路，手机端应直接强制 `grid-template-columns: 1fr`
3. `welcome-top` 和 `welcome-feature` 在小屏下不只是“单列”，还要同步清掉内部组件的固定高度、固定最小高度和额外左内边距
4. 首页大卡片建议改成“内容优先流式布局”：
   - 日历卡片单独一行
   - 木鱼/番茄钟单独一行
   - 备忘录单独一行
   - 装饰图和文案单独一行或直接隐藏装饰图

### 2. 顶部 Header 同时塞了标题、翻页时钟、写文章按钮、头像昵称

风险位置：

- `Layout.vue:42-55`
- `Layout.vue:322-374`

这正是你截图里“番茄钟 + 写文章 + 头像挤在一起”的直接来源。

解决方案：

1. 手机端不要保留桌面端同一行结构，顶部应拆成两层或三层：
   - 第一层：页面标题/副标题
   - 第二层：时钟
   - 第三层：写文章按钮 + 用户头像入口
2. `header-right` 在手机端不要继续 `justify-content: space-between` 强行拉满一行，改成：
   - `flex-wrap: wrap`
   - 或者直接 `flex-direction: column`
3. 用户昵称在手机端不要完整展示，建议：
   - 只保留头像
   - 或最多显示 4 到 6 个字，超出省略
4. “写文章”按钮在手机端建议改为：
   - 只显示图标 + 短文案
   - 或移到浮动按钮/底部操作区
5. 页面副标题在手机端可以隐藏，优先保住操作区和主内容

### 3. 翻页时钟本身宽度过大，小屏会天然占满一整行

风险位置：

- `FlipClock.vue:90-98`
- `FlipClock.vue:179-190`

当前问题：

- 单个数字卡片宽 48px，手机端仍有 42px
- 时钟 label、数字块、冒号间距都偏大
- 小屏时用了 `justify-content: space-between`，会把整体拉得更散

解决方案：

1. 手机端把时钟视为“独占一行的组件”，不要再和按钮头像抢横向空间
2. 在 `<= 480px` 时继续缩小：
   - 数字块宽高
   - 数字字号
   - 数字间距
   - 冒号间距
3. `clock-group` 手机端不要 `space-between`，改成 `justify-content: flex-start` 或 `center`
4. 如果还想更稳，可以在超小屏直接降级为普通文本时间 `10:15`
5. 时钟标签“此刻时间”可隐藏，只保留数字

### 4. 日历卡片内部用了绝对定位吉祥物，和日期内容争抢空间

风险位置：

- `TodayCalendar.vue:39`
- `TodayCalendar.vue:51-64`
- `TodayCalendar.vue:96`

当前问题：

- 卡片 `min-height: 250px`
- 吉祥物 `position: absolute`
- 日期字号 76px
- 手机上虽然缩小了吉祥物位置，但没有改变布局模型

解决方案：

1. 手机端取消吉祥物绝对定位，改为正常文档流：
   - 放到日期下方
   - 或放到卡片底部
2. 超小屏下直接隐藏吉祥物，优先保住日期和文案
3. 日期字号做分级缩放：
   - 桌面大字
   - 平板中号
   - 手机小号
4. 去掉手机端固定 `min-height`，让卡片高度由内容撑开
5. `TODAY`、星期、日期、文案建议在手机端统一左对齐，减少视觉碰撞

### 5. 木鱼组件的标题和点击区域也偏大

风险位置：

- `MuyuWidget.vue:99-113`
- `MuyuWidget.vue:126-157`

当前问题：

- 标题和数字都是 28px
- 木鱼按钮宽 300px
- 在 360px 手机宽度下，视觉上会非常顶

解决方案：

1. 手机端把“今日摸鱼指数”这一行改成上下布局：
   - 第一行标题
   - 第二行计数
2. 木鱼按钮宽度不要固定 300px，改成：
   - `width: 100%`
   - 配合 `max-width`
3. 图片大小用 `clamp()` 或分断点控制，不要让组件在手机里视觉过重
4. 飘字 `+1` 的字号也应缩小，否则容易压住图片和周围内容

### 6. 备忘录也存在装饰图绝对定位问题

风险位置：

- `MemoBoard.vue:253-266`
- `MemoBoard.vue:497-505`

解决方案：

1. 手机端把右上角吉祥物直接隐藏，或者移动到标题下方
2. 备忘项 `grid` 在超小屏可以改成两行：
   - 第一行：勾选 + 内容
   - 第二行：操作按钮
3. 备忘录滚动区最大高度不要写死过高，避免首页第一屏被它吃掉

## 二、首页推荐的整体改法

如果你后面真的要动首页，建议按下面这个方向统一处理：

1. 手机端首页改成纯单列流式布局，不保留桌面端“横向并排展示感”
2. 顶部 Header 只保留最重要信息：
   - 标题
   - 时间
   - 一个主操作按钮
   - 用户头像入口
3. 所有装饰性图片在 `<= 480px` 时默认隐藏
4. 所有大字号数字卡片都要再做一轮手机端缩放
5. 所有固定宽度按钮、卡片、面板都改成：
   - `width: 100%`
   - `max-width`
   - `min-width: 0`
6. 手机端优先保证：
   - 不重叠
   - 不横向滚动
   - 点击区域够大
   - 首屏能快速看到主内容

## 四、最容易漏掉的移动端问题清单

下面这些问题，你这个项目里后续很可能还会继续遇到：

### 1. 固定宽度

典型表现：

- `width: 300px`
- `width: 500px`
- 弹窗 `width="760px"` / `width="980px"`

解决方案：

1. 输入框、按钮、卡片优先用 `width: 100%`
2. 需要上限时再加 `max-width`
3. 弹窗统一改成百分比宽度，并给超高内容加滚动

### 2. 固定字号过大

典型表现：

- 首页大数字
- 文章标题
- 摸鱼指数大字

解决方案：

1. 大字统一用断点缩放
2. 可以优先考虑 `clamp()`，减少重复写媒体查询

### 3. 绝对定位装饰图

典型表现：

- 日历吉祥物
- 备忘录吉祥物

解决方案：

1. 手机端取消绝对定位
2. 装饰图优先隐藏，不要牺牲正文可读性

### 4. 单行省略过多

典型表现：

- 标题 `white-space: nowrap`
- 路径字段强制单行

解决方案：

1. 标题优先两行截断
2. 路径类字段优先换行或局部横向滚动

### 5. 分页组件过长

典型表现：

- `layout="total, sizes, prev, pager, next, jumper"`

解决方案：

1. 手机端精简分页布局
2. 甚至可以改为“加载更多”

### 6. 表单仍按桌面端左标签布局

典型表现：

- `label-width="100px"`

解决方案：

1. 手机端统一改 `label-position="top"`
2. 输入框、选择器、日期控件统一占满容器宽度

## 五、建议的处理优先级

### P0：先解决首页首屏错位

1. `Layout.vue` 顶部 Header 拆层
2. `FlipClock.vue` 时钟缩小并独占一行
3. `TodayCalendar.vue` 去掉手机端绝对定位吉祥物
4. `Home.vue` 首页主区彻底单列化

### P1：再解决所有弹窗和分页

1. `Profile.vue`、`ResourceList.vue` 的弹窗宽度改百分比
2. 全站分页做手机端简化

### P2：最后统一扫固定宽度和大字号

1. 搜索框固定宽度
2. 按钮固定宽度
3. 大标题和大数字字号
4. 所有 `nowrap`

## 六、一句话结论

你现在的主要问题不是某一个组件坏了，而是**整体布局仍然按桌面端思路搭建，手机端只做了轻量缩小，没有真正改成单列流式布局**。后面如果要稳，首页、Header、弹窗、分页、表单这五类地方要优先统一改造。
