# 后台管理首页后端开发文档

## 一、文档说明

### 1.1 基本信息

| 项目 | 说明 |
|------|------|
| 所属项目 | 校园墙后端 |
| 模块名称 | 后台管理首页 |
| 技术栈 | Spring Boot 3 + MyBatis + MySQL |
| 接口基础路径 | `http://localhost:8080/api/admin/dashboard` |
| 认证方式 | JWT Token |
| 权限要求 | 仅管理员可访问 |
| 文档版本 | v1.0 |
| 创建日期 | 2026-06-26 |

### 1.2 开发目标

提供一组仅管理员可访问的后台首页接口，支持前端使用 ECharts 展示以下 8 块数据：

1. 用户总数、帖子总数、资料总数、下载总次数
2. 近 7 天用户注册趋势
3. 近 7 天发帖趋势
4. 近 7 天资料上传趋势
5. 文件类型分布
6. 热门资料 Top10
7. 文件夹上传成功/失败统计
8. 最新上传批次列表

核心要求：

- 所有接口仅管理员可调用
- 接口字段与前端文档完全一致
- 统计口径固定，避免前后端理解不一致
- 返回结构统一使用 `Result<T>`

## 二、权限设计

### 2.1 访问规则

后台首页所有接口必须满足：

- 用户已登录
- 当前用户 `role = 1`

根据现有项目文档，用户角色字段：

```java
private Integer role; // 0-普通用户，1-管理员
```

### 2.2 权限拦截建议

推荐做法：

- 先通过 JWT 解析当前用户
- 在 Controller 或拦截器中校验角色
- 非管理员统一返回 `403`

返回示例：

```json
{
  "code": 403,
  "message": "仅管理员可访问后台",
  "data": null
}
```

## 六、接口设计

### 6.1 概览统计

- 请求方式：`GET`
- 请求路径：`/api/admin/dashboard/overview`
- 是否登录：是
- 是否管理员：是

返回 VO：

```java
public class AdminDashboardOverviewVO {
    private Long userCount;
    private Long postCount;
    private Long resourceCount;
    private Long totalDownloadCount;
}
```

返回示例：

```json
{
  "code": 200,
  "message": "操作成功",
  "data": {
    "userCount": 125,
    "postCount": 348,
    "resourceCount": 86,
    "totalDownloadCount": 1542
  }
}
```

统计口径：

- `userCount`：用户表总数
- `postCount`：帖子表总数
- `resourceCount`：资料表总数
- `totalDownloadCount`：资料表 `download_count` 总和

### 6.2 用户注册趋势

- 请求方式：`GET`
- 请求路径：`/api/admin/dashboard/user-register-trend`

请求参数：

| 参数名 | 类型 | 必填 | 说明 |
|------|------|------|------|
| days | int | 否 | 默认 7，建议限制 7/30 |

返回 VO：

```java
public class TrendItemVO {
    private String date;
    private Long count;
}
```

返回示例：

```json
[
  { "date": "2026-06-20", "count": 3 },
  { "date": "2026-06-21", "count": 5 }
]
```

统计口径：

- 按用户注册时间按天分组
- 没有数据的日期也要补 0

### 6.3 发帖趋势

- 请求方式：`GET`
- 请求路径：`/api/admin/dashboard/post-publish-trend`

返回结构与 `TrendItemVO` 一致。

统计口径：

- 按帖子发布时间按天分组
- 没有数据的日期补 0

### 6.4 资料上传趋势

- 请求方式：`GET`
- 请求路径：`/api/admin/dashboard/resource-upload-trend`

返回结构与 `TrendItemVO` 一致。

统计口径：

- 按资料创建时间按天分组
- 单文件上传和文件夹上传中的文件都计入上传数
- 没有数据的日期补 0

### 6.5 文件类型分布

- 请求方式：`GET`
- 请求路径：`/api/admin/dashboard/resource-file-type-distribution`

返回 VO：

```java
public class FileTypeDistributionVO {
    private String fileType;
    private Long count;
}
```

返回示例：

```json
[
  { "fileType": "pdf", "count": 42 },
  { "fileType": "doc", "count": 15 },
  { "fileType": "docx", "count": 29 }
]
```

统计口径：

- 按 `resource.file_type` 分组统计
- 文件类型统一转小写

### 6.6 热门资料 Top10

- 请求方式：`GET`
- 请求路径：`/api/admin/dashboard/resource-download-top`

请求参数：

| 参数名 | 类型 | 必填 | 说明 |
|------|------|------|------|
| limit | int | 否 | 默认 10，最大 20 |

返回 VO：

```java
public class HotResourceVO {
    private Long id;
    private String title;
    private Long downloadCount;
    private String fileType;
}
```

返回示例：

```json
[
  {
    "id": 12,
    "title": "高等数学期末复习资料",
    "downloadCount": 156,
    "fileType": "pdf"
  }
]
```

统计口径：

- 按 `download_count` 倒序
- 相同下载量时按最新创建时间倒序

### 6.7 文件夹上传成功/失败统计

- 请求方式：`GET`
- 请求路径：`/api/admin/dashboard/folder-upload-stat`

返回 VO：

```java
public class FolderUploadStatVO {
    private Long totalBatchCount;
    private Long successBatchCount;
    private Long partialSuccessBatchCount;
    private Long failedBatchCount;
}
```

返回示例：

```json
{
  "totalBatchCount": 38,
  "successBatchCount": 24,
  "partialSuccessBatchCount": 11,
  "failedBatchCount": 3
}
```

统计口径基于 `resource_upload_batch.status`：

| status | 含义 |
|------|------|
| 1 | 全部成功 |
| 2 | 部分成功 |
| 3 | 全部失败 |

### 6.8 最新上传批次列表

- 请求方式：`GET`
- 请求路径：`/api/admin/dashboard/latest-upload-batches`

请求参数：

| 参数名 | 类型 | 必填 | 说明 |
|------|------|------|------|
| limit | int | 否 | 默认 10，最大 20 |

返回 VO：

```java
public class LatestUploadBatchVO {
    private String batchNo;
    private String folderName;
    private String uploaderName;
    private Integer totalCount;
    private Integer successCount;
    private Integer failCount;
    private Long totalSize;
    private Integer status;
    private String statusText;
    private String createTime;
}
```

返回示例：

```json
[
  {
    "batchNo": "RB202606260001",
    "folderName": "高数",
    "uploaderName": "小王",
    "totalCount": 8,
    "successCount": 8,
    "failCount": 0,
    "totalSize": 18602496,
    "status": 1,
    "statusText": "全部成功",
    "createTime": "2026-06-26 22:30:00"
  }
]
```

## 七、Controller 设计

### 7.1 接口定义建议

```java
@RestController
@RequestMapping("/api/admin/dashboard")
public class AdminDashboardController {

    @GetMapping("/overview")
    public Result<AdminDashboardOverviewVO> getOverview() { }

    @GetMapping("/user-register-trend")
    public Result<List<TrendItemVO>> getUserRegisterTrend(@RequestParam(defaultValue = "7") Integer days) { }

    @GetMapping("/post-publish-trend")
    public Result<List<TrendItemVO>> getPostPublishTrend(@RequestParam(defaultValue = "7") Integer days) { }

    @GetMapping("/resource-upload-trend")
    public Result<List<TrendItemVO>> getResourceUploadTrend(@RequestParam(defaultValue = "7") Integer days) { }

    @GetMapping("/resource-file-type-distribution")
    public Result<List<FileTypeDistributionVO>> getResourceFileTypeDistribution() { }

    @GetMapping("/resource-download-top")
    public Result<List<HotResourceVO>> getResourceDownloadTop(@RequestParam(defaultValue = "10") Integer limit) { }

    @GetMapping("/folder-upload-stat")
    public Result<FolderUploadStatVO> getFolderUploadStat() { }

    @GetMapping("/latest-upload-batches")
    public Result<List<LatestUploadBatchVO>> getLatestUploadBatches(@RequestParam(defaultValue = "10") Integer limit) { }
}
```

### 7.2 Controller 层职责

- 校验管理员身份
- 校验 `days`、`limit` 参数范围
- 调用 Service 聚合数据
- 返回统一 `Result<T>`

## 八、Service 设计

### 8.1 Service 接口建议

```java
public interface AdminDashboardService {
    AdminDashboardOverviewVO getOverview();
    List<TrendItemVO> getUserRegisterTrend(Integer days);
    List<TrendItemVO> getPostPublishTrend(Integer days);
    List<TrendItemVO> getResourceUploadTrend(Integer days);
    List<FileTypeDistributionVO> getResourceFileTypeDistribution();
    List<HotResourceVO> getResourceDownloadTop(Integer limit);
    FolderUploadStatVO getFolderUploadStat();
    List<LatestUploadBatchVO> getLatestUploadBatches(Integer limit);
}
```

### 8.2 Service 实现要点

- 趋势类数据统一补齐空日期
- 统计类数据统一转 `0`，不要返回 `null`
- 列表类数据为空时返回空数组
- `statusText` 在 Service 层组装，前端直接显示

## 九、SQL 统计口径建议

以下 SQL 为开发思路，字段名需按实际表结构调整。

### 9.1 概览统计

```sql
SELECT COUNT(*) FROM user;
SELECT COUNT(*) FROM post;
SELECT COUNT(*) FROM resource;
SELECT IFNULL(SUM(download_count), 0) FROM resource;
```

### 9.2 近 7 天注册趋势

```sql
SELECT DATE(create_time) AS stat_date, COUNT(*) AS stat_count
FROM user
WHERE create_time >= DATE_SUB(CURDATE(), INTERVAL 6 DAY)
GROUP BY DATE(create_time)
ORDER BY stat_date;
```

### 9.3 近 7 天发帖趋势

```sql
SELECT DATE(create_time) AS stat_date, COUNT(*) AS stat_count
FROM post
WHERE create_time >= DATE_SUB(CURDATE(), INTERVAL 6 DAY)
GROUP BY DATE(create_time)
ORDER BY stat_date;
```

### 9.4 近 7 天资料上传趋势

```sql
SELECT DATE(create_time) AS stat_date, COUNT(*) AS stat_count
FROM resource
WHERE create_time >= DATE_SUB(CURDATE(), INTERVAL 6 DAY)
GROUP BY DATE(create_time)
ORDER BY stat_date;
```

### 9.5 文件类型分布

```sql
SELECT LOWER(file_type) AS file_type, COUNT(*) AS stat_count
FROM resource
GROUP BY LOWER(file_type)
ORDER BY stat_count DESC;
```

### 9.6 热门资料 Top10

```sql
SELECT id, title, download_count, file_type
FROM resource
ORDER BY download_count DESC, create_time DESC
LIMIT 10;
```

### 9.7 文件夹上传成功/失败统计

```sql
SELECT
    COUNT(*) AS total_batch_count,
    SUM(CASE WHEN status = 1 THEN 1 ELSE 0 END) AS success_batch_count,
    SUM(CASE WHEN status = 2 THEN 1 ELSE 0 END) AS partial_success_batch_count,
    SUM(CASE WHEN status = 3 THEN 1 ELSE 0 END) AS failed_batch_count
FROM resource_upload_batch;
```

### 9.8 最新上传批次列表

```sql
SELECT
    b.batch_no,
    b.folder_name,
    u.nickname AS uploader_name,
    b.total_count,
    b.success_count,
    b.fail_count,
    b.total_size,
    b.status,
    b.created_at
FROM resource_upload_batch b
LEFT JOIN user u ON b.user_id = u.id
ORDER BY b.created_at DESC
LIMIT 10;
```

> 若 `nickname` 为空，可回退到 `username`。

## 十一、异常处理

### 11.1 常见错误码

| code | 含义 |
|------|------|
| 200 | 成功 |
| 401 | 未登录或登录失效 |
| 403 | 非管理员访问 |
| 400 | 参数不合法 |
| 500 | 服务器异常 |

### 11.2 参数校验建议

| 参数 | 规则 |
|------|------|
| days | 仅允许 `7`、`30` |
| limit | 默认 10，最大 20 |

不合法返回：

```json
{
  "code": 400,
  "message": "请求参数不合法",
  "data": null
}
```

## 十二、联调验收标准

满足以下条件即可认为后端开发完成：

1. 所有接口仅管理员可访问
2. 8 个接口均能返回与前端文档一致的字段
3. 趋势数据能补齐空日期
4. 统计字段不返回 `null`
5. 热门资料 Top10 可按下载量正确排序
6. 文件夹上传统计可正确区分成功/部分成功/失败
7. 最新上传批次列表可正确返回上传人、状态文案、时间

---

## 十三、推荐实现结论

本次后台首页后端最稳妥的方案是：

- 新增 `/api/admin/dashboard/*` 一组管理员专用接口
- 所有接口统一走 JWT + 角色校验
- 统计接口按前端首页模块拆分
- 所有趋势接口统一按天补 0
- 所有字段与前端文档一一对应

这样前端可以直接按模块接入 ECharts，也方便后续继续新增用户管理、资料审计、异常统计等后台能力。
