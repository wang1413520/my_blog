# 学习资料上传文件夹前端开发文档

## 一、文档说明

### 1.1 基本信息

| 项目 | 说明 |
|------|------|
| 所属项目 | 校园墙前端（`qianduan-campus`） |
| 模块名称 | 学习资料 |
| 技术栈 | Vue 3 + Element Plus + Vite |
| 对接后端 | `POST /api/resource/upload/folder` |
| 文档版本 | v1.0 |
| 创建日期 | 2026-06-26 |

### 1.2 开发目标

在现有“上传资料（单文件）”按钮右侧新增“上传文件夹”按钮，支持用户一次选择整个资料文件夹并批量上传。

本次改造要求：

- 不影响现有单文件上传逻辑
- 前后端字段完全对齐
- 上传成功后仍复用现有资料列表页展示
- 支持部分成功场景

## 三、交互设计

### 3.1 用户流程

1. 用户点击 `上传文件夹`
2. 前端打开本地文件夹选择器
3. 用户选择一个文件夹
4. 前端读取该文件夹下所有文件及相对路径
5. 弹出“上传文件夹”确认弹窗
6. 用户填写批次描述后提交
7. 前端调用后端接口 `POST /api/resource/upload/folder`
8. 上传完成后提示结果并刷新资料列表

### 3.2 浏览器实现方式

文件夹上传不建议直接依赖 `el-upload`，而是使用隐藏的原生 `input`：

```html
<input
  ref="folderInputRef"
  type="file"
  webkitdirectory
  multiple
  style="display: none"
  @change="handleFolderSelect"
/>
```

说明：

- `webkitdirectory`：允许选择文件夹
- `multiple`：文件夹内会返回多个文件
- 每个文件对象可通过 `file.webkitRelativePath` 读取相对路径

> 推荐浏览器：Chrome、Edge。该方案与 Windows + Chrome/Edge 的实际使用场景最匹配。

## 四、前端数据结构

### 4.1 响应式状态

```javascript
const folderInputRef = ref(null)
const folderUploadDialogVisible = ref(false)
const folderUploadLoading = ref(false)

const folderUploadForm = reactive({
  folderName: '',
  description: '',
  files: [],
  relativePaths: [],
  totalSize: 0
})
```

### 4.2 文件对象说明

`folderUploadForm.files` 保存浏览器返回的原始 `File` 对象数组。  
`folderUploadForm.relativePaths` 保存与 `files` 一一对应的相对路径数组。

示例：

```javascript
files[0].name = '第一章重点.pdf'
files[0].webkitRelativePath = '高等数学复习资料/第一章/第一章重点.pdf'

folderName = '高等数学复习资料'
relativePaths[0] = '第一章/第一章重点.pdf'
```

注意：

- `folderName` 单独传给后端
- `relativePaths[]` 中不要再带根目录名，避免重复

## 五、接口对接协议

这一节必须与后端文档保持一致。

### 5.1 接口信息

- 请求方式：`POST`
- 请求路径：`/api/resource/upload/folder`
- 是否登录：是
- Content-Type：`multipart/form-data`

### 5.2 请求参数

| 参数名 | 类型 | 必填 | 说明 |
|------|------|------|------|
| folderName | string | 是 | 用户选择的根文件夹名称 |
| description | string | 否 | 整个文件夹批次的描述，最长 500 字 |
| files | file[] | 是 | 文件数组，支持 `pdf/doc/docx` |
| relativePaths | string[] | 是 | 与 `files` 顺序一致的相对路径数组 |

### 5.3 参数组装规则

`FormData` 必须按下面方式追加：

```javascript
const formData = new FormData()
formData.append('folderName', folderUploadForm.folderName)

if (folderUploadForm.description) {
  formData.append('description', folderUploadForm.description)
}

folderUploadForm.files.forEach(file => {
  formData.append('files', file)
})

folderUploadForm.relativePaths.forEach(path => {
  formData.append('relativePaths', path)
})
```

约束：

- `files[i]` 必须和 `relativePaths[i]` 一一对应
- 两个数组长度必须相等
- 前端不要自行打乱文件顺序

### 5.4 返回结构

后端统一返回 `Result<T>`：

```json
{
  "code": 200,
  "message": "文件夹上传成功",
  "data": {
    "batchNo": "RB202606260001",
    "folderName": "高等数学复习资料",
    "totalCount": 8,
    "successCount": 8,
    "failCount": 0,
    "totalSize": 18602496,
    "records": [
      {
        "id": 101,
        "title": "第一章重点",
        "fileType": "pdf",
        "fileSize": 2048576,
        "folderName": "高等数学复习资料",
        "relativePath": "第一章/第一章重点.pdf",
        "batchNo": "RB202606260001",
        "createTime": "2026-06-26 22:30:00"
      }
    ],
    "failedFiles": []
  }
}
```

### 5.5 关键对接约束

由于当前前端 `src/utils/request.js` 中只有 `code === 200` 才会走成功分支，所以后端在以下两种场景都必须返回 `code: 200`：

- 全部文件上传成功
- 部分文件上传成功

区别方式：

- `message` 用于提示文案
- `failCount` 判断是否部分失败
- `failedFiles` 展示失败明细

前端不要依赖 `206`、`207` 等状态码作为“部分成功”标识。

## 六、前端校验规则

### 6.1 选择文件夹后立即校验

| 校验项 | 规则 |
|------|------|
| 是否选择文件 | 至少 1 个文件 |
| 文件数量 | 最多 100 个 |
| 单文件大小 | 不超过 50MB |
| 总大小 | 不超过 500MB |
| 文件类型 | 仅允许 `pdf/doc/docx` |
| 相对路径 | 不允许为空 |

### 6.2 失败提示建议

| 场景 | 提示文案 |
|------|------|
| 未选择任何文件 | `所选文件夹中没有可上传文件` |
| 文件数量超限 | `文件夹中文件数量不能超过 100 个` |
| 文件类型不支持 | `仅支持上传 pdf/doc/docx 文件` |
| 单文件过大 | `单个文件不能超过 50MB` |
| 总大小超限 | `整个文件夹总大小不能超过 500MB` |

## 七、页面交互细节

### 7.1 上传文件夹按钮

示例：

```html
<el-button
  v-if="userStore.isLogin()"
  type="warning"
  @click="openFolderSelector"
>
  上传文件夹
</el-button>
```

### 7.2 选择文件夹

```javascript
const openFolderSelector = () => {
  folderInputRef.value && (folderInputRef.value.value = '')
  folderInputRef.value?.click()
}
```

### 7.3 解析文件夹

```javascript
const handleFolderSelect = (event) => {
  const fileList = Array.from(event.target.files || [])
  if (!fileList.length) return

  const firstPath = fileList[0].webkitRelativePath || ''
  const rootFolderName = firstPath.split('/')[0]

  folderUploadForm.folderName = rootFolderName
  folderUploadForm.files = fileList
  folderUploadForm.relativePaths = fileList.map(file => {
    const fullPath = file.webkitRelativePath || file.name
    return fullPath.replace(`${rootFolderName}/`, '')
  })
  folderUploadForm.totalSize = fileList.reduce((sum, file) => sum + file.size, 0)

  folderUploadDialogVisible.value = true
}
```

### 7.4 上传提交

```javascript
const submitFolderUpload = async () => {
  folderUploadLoading.value = true
  try {
    const formData = new FormData()
    formData.append('folderName', folderUploadForm.folderName)

    if (folderUploadForm.description) {
      formData.append('description', folderUploadForm.description)
    }

    folderUploadForm.files.forEach(file => {
      formData.append('files', file)
    })

    folderUploadForm.relativePaths.forEach(path => {
      formData.append('relativePaths', path)
    })

    const result = await resourceAPI.uploadResourceFolder(formData)

    if (result.failCount > 0) {
      ElMessage.warning(`上传完成，成功 ${result.successCount} 个，失败 ${result.failCount} 个`)
    } else {
      ElMessage.success(`文件夹上传成功，共 ${result.successCount} 个文件`)
    }

    folderUploadDialogVisible.value = false
    resetFolderUploadForm()
    loadResourceList()
  } catch (error) {
    console.error('文件夹上传失败:', error)
  } finally {
    folderUploadLoading.value = false
  }
}
```

## 八、API 封装要求

在 `src/api/resource.js` 中新增：

```javascript
uploadResourceFolder(formData) {
  return request.post('/resource/upload/folder', formData, {
    headers: {
      'Content-Type': 'multipart/form-data'
    }
  })
}
```

完整接口层建议保留为：

```javascript
export const resourceAPI = {
  uploadResource(formData) {
    return request.post('/resource/upload', formData, {
      headers: {
        'Content-Type': 'multipart/form-data'
      }
    })
  },

  uploadResourceFolder(formData) {
    return request.post('/resource/upload/folder', formData, {
      headers: {
        'Content-Type': 'multipart/form-data'
      }
    })
  },

  getResourceList(params) {
    return request.get('/resource/list', { params })
  },

  getResourceDetail(id) {
    return request.get(`/resource/${id}`)
  },

  downloadResource(id) {
    return `http://localhost:8080/api/resource/download/${id}`
  },

  deleteResource(id) {
    return request.delete(`/resource/${id}`)
  }
}
```

## 九、与现有资料列表的衔接方式

后端仍然把文件夹中的每个文件作为一条独立资料记录写入 `resource` 表，因此前端资料列表页无需重构。

列表接口建议新增返回字段，但前端首版可以只做兼容读取：

| 字段 | 是否必用 | 说明 |
|------|------|------|
| uploadType | 否 | `single` 或 `folder` |
| folderName | 否 | 所属文件夹名 |
| relativePath | 否 | 文件夹内相对路径 |
| batchNo | 否 | 同一次文件夹上传批次号 |

可选增强展示：

- 文件夹上传的资料在卡片上增加 `文件夹上传` 标签
- 鼠标悬停时展示 `folderName / relativePath`

## 十、异常处理

### 10.1 前端需要覆盖的场景

- 用户未登录时不显示“上传文件夹”按钮
- 用户选择文件夹后取消提交
- 上传过程中网络中断
- 后端返回部分成功
- 后端校验失败

### 10.2 展示建议

- 全成功：`ElMessage.success`
- 部分成功：`ElMessage.warning`
- 全失败：`ElMessage.error`

如果 `failedFiles.length > 0`，建议弹出详情面板展示：

| 字段 | 说明 |
|------|------|
| fileName | 文件名 |
| relativePath | 相对路径 |
| reason | 失败原因 |

## 十一、联调验收标准

满足以下条件即可认为前端对接完成：

1. 点击 `上传文件夹` 能正常选择本地文件夹
2. 能正确解析 `folderName` 和每个文件的 `relativePath`
3. 提交时请求字段与后端文档完全一致
4. 上传成功后可刷新并看到资料列表新增记录
5. 部分成功时前端不会被拦截器判定为失败
6. 后端返回的 `records`、`failedFiles` 可被前端正常读取

---

## 十二、推荐实现结论

本次前端最稳妥的实现方案是：

- 保留现有单文件上传弹窗
- 新增独立“上传文件夹”按钮和弹窗
- 文件夹选择使用原生 `input + webkitdirectory`
- 接口单独走 `/api/resource/upload/folder`
- 上传完成后继续复用现有资料列表页

这样改动最小，且能与后端批量上传接口稳定对接。
