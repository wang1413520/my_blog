# 后台管理首页前端开发文档

## 一、文档说明

### 1.1 基本信息

| 项目 | 说明 |
|------|------|
| 所属项目 | 校园墙前端（`qianduan-campus`） |
| 模块名称 | 后台管理首页 |
| 技术栈 | Vue 3 + Element Plus + Vite + ECharts |
| 对接后端 | `/api/admin/dashboard/*` |
| 权限要求 | 仅管理员可访问 |
| 文档版本 | v1.0 |
| 创建日期 | 2026-06-26 |

### 1.2 开发目标

新增一个“后台管理首页”页面，仅管理员可进入，首页展示以下 8 块核心数据：

1. 用户总数、帖子总数、资料总数、下载总次数
2. 近 7 天用户注册趋势
3. 近 7 天发帖趋势
4. 近 7 天资料上传趋势
5. 文件类型分布
6. 热门资料 Top10
7. 文件夹上传成功/失败统计
8. 最新上传批次列表

本次前端开发要求：

- 只允许 `role === 1` 的管理员进入
- 页面风格偏后台数据看板
- 图表使用 ECharts
- 与后端接口字段完全对齐
- 页面加载失败时可单独降级，不影响其他卡片展示

## 三、路由与权限设计

### 3.1 路由建议

在 `src/router/index.js` 中新增：

```javascript
{
  path: '/admin/dashboard',
  name: 'AdminDashboard',
  component: () => import('@/views/Admin/AdminDashboard.vue'),
  meta: {
    title: '后台管理',
    requiresAuth: true,
    requiresAdmin: true
  }
}
```

### 3.2 权限校验

进入后台首页前，前端需要同时校验：

- 用户已登录
- `userStore.userInfo?.role === 1`

建议在全局路由守卫中处理：

```javascript
router.beforeEach((to, from, next) => {
  const userStore = useUserStore()

  if (to.meta.requiresAuth && !userStore.isLogin()) {
    next('/login')
    return
  }

  if (to.meta.requiresAdmin && userStore.userInfo?.role !== 1) {
    ElMessage.error('仅管理员可访问后台')
    next('/')
    return
  }

  next()
})
```

### 3.3 导航入口

建议仅当 `userInfo.role === 1` 时，在侧边栏显示“后台管理”菜单。

## 四、页面结构设计

### 4.1 页面布局

后台首页建议采用以下结构：

```text
+------------------------------------------------------+
| 标题区：后台管理首页 / 数据概览                       |
+------------------------------------------------------+
| 统计卡片区：4 张概览卡                                |
| 用户总数 | 帖子总数 | 资料总数 | 下载总次数           |
+------------------------------------------------------+
| 图表区第一行                                          |
| 近7天用户注册趋势 | 近7天发帖趋势                    |
+------------------------------------------------------+
| 图表区第二行                                          |
| 近7天资料上传趋势 | 文件类型分布                     |
+------------------------------------------------------+
| 图表区第三行                                          |
| 热门资料Top10    | 文件夹上传成功/失败统计           |
+------------------------------------------------------+
| 列表区：最新上传批次列表                               |
+------------------------------------------------------+
```

### 4.2 页面视觉建议

- 顶部使用后台风格标题区
- 概览卡片用 `el-card`
- 图表区域统一高度，避免页面抖动
- 列表区用 `el-table`
- 页面整体保留与现有项目一致的浅色风格，但比普通页面更“运营后台”

## 八、页面加载流程

### 8.1 首次进入页面

建议使用 `Promise.allSettled` 并发加载，避免单个接口失败导致整个页面空白。

```javascript
const loadDashboardData = async () => {
  pageLoading.value = true

  const [
    overviewResult,
    registerResult,
    postResult,
    resourceResult,
    fileTypeResult,
    hotResourceResult,
    folderStatResult,
    latestBatchResult
  ] = await Promise.allSettled([
    adminAPI.getDashboardOverview(),
    adminAPI.getUserRegisterTrend({ days: 7 }),
    adminAPI.getPostPublishTrend({ days: 7 }),
    adminAPI.getResourceUploadTrend({ days: 7 }),
    adminAPI.getResourceFileTypeDistribution(),
    adminAPI.getResourceDownloadTop({ limit: 10 }),
    adminAPI.getFolderUploadStat(),
    adminAPI.getLatestUploadBatches({ limit: 10 })
  ])

  pageLoading.value = false
}
```

### 8.2 加载策略建议

- 概览卡片失败：显示 `--`
- 单个图表失败：显示空态，不影响其他模块
- 上传批次列表失败：显示 `暂无数据`

## 九、ECharts 设计方案

### 9.1 注册趋势图

- 图表类型：折线图
- X 轴：日期
- Y 轴：注册人数

```javascript
const option = {
  tooltip: { trigger: 'axis' },
  xAxis: {
    type: 'category',
    data: registerTrend.value.map(item => item.date)
  },
  yAxis: { type: 'value' },
  series: [
    {
      name: '注册人数',
      type: 'line',
      smooth: true,
      data: registerTrend.value.map(item => item.count)
    }
  ]
}
```

### 9.2 发帖趋势图

- 图表类型：柱状图
- X 轴：日期
- Y 轴：发帖数

### 9.3 资料上传趋势图

- 图表类型：折线图或面积图
- X 轴：日期
- Y 轴：上传数

### 9.4 文件类型分布图

- 图表类型：环形饼图
- 数据字段：
  - `name` ← `fileType`
  - `value` ← `count`

### 9.5 热门资料 Top10

- 图表类型：横向条形图
- Y 轴：资料标题
- X 轴：下载次数

### 9.6 文件夹上传成功/失败统计

- 图表类型：饼图
- 维度：
  - 全部成功
  - 部分成功
  - 全部失败

表头建议：

| 列名 | 字段 |
|------|------|
| 批次号 | `batchNo` |
| 文件夹名 | `folderName` |
| 上传人 | `uploaderName` |
| 文件数 | `totalCount` |
| 成功数 | `successCount` |
| 失败数 | `failCount` |
| 总大小 | `totalSize` |
| 状态 | `statusText` |
| 上传时间 | `createTime` |

- `totalSize` 需要调用 `formatFileSize`
- `statusText` 可直接显示后端返回值

### 11.2 异常提示

建议仅在控制台打印详细错误，页面上使用弱提示：

- `后台首页部分数据加载失败`

不要在首页连续弹出多个 `ElMessage.error`，避免管理员刚进后台就被提示轰炸。

## 十二、联调验收标准

满足以下条件即可认为前端开发完成：

1. 非管理员无法进入后台首页
2. 管理员可正常进入后台首页
3. 4 张概览卡片可正确显示总数
4. 6 个图表可正常渲染
5. 最新上传批次表格可正常显示
6. 任意单个接口失败不会导致整个页面白屏
7. 所有字段与后端文档完全对齐

---

## 十三、推荐实现结论

本次后台首页前端最稳妥的实现方案是：

- 新增独立 `AdminDashboard.vue`
- 通过 `meta.requiresAdmin` 做管理员路由控制
- 接口按 8 个模块拆分，便于单独维护
- 图表全部使用 ECharts 原生实例
- 页面加载采用 `Promise.allSettled`

这样页面最接近真正后台首页的使用方式，也方便后续继续扩展用户管理、资料管理、审计日志等模块。
