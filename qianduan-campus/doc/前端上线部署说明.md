# 前端上线部署说明

## 一、构建

```bash
npm install
npm run build
```

构建产物目录：

```text
dist/
```

---

## 二、Nginx 配置要点

本项目使用：

- 前端路由：`createWebHistory()`
- 接口前缀：`/api`

因此生产环境必须同时配置：

1. `/api` 反向代理
2. `try_files` history fallback

---

## 三、参考 Nginx 配置

```nginx
server {
    listen 80;
    server_name your-domain.com;

    root /opt/qianduan-campus/dist;
    index index.html;

    location / {
        try_files $uri $uri/ /index.html;
    }

    location /api/ {
        proxy_pass http://127.0.0.1:8080;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
        client_max_body_size 550m;
    }
}
```

---

## 四、为什么必须这样配

### 4.1 `/api` 反代

前端代码中的接口基地址为：

```text
/api
```

这意味着浏览器请求会发到当前域名下的 `/api/...`，需要由 Nginx 代理到后端服务。

### 4.2 `try_files`

项目使用 History 路由模式。

如果用户直接访问：

```text
/post/detail/123
```

Nginx 必须把这类请求回退到 `index.html`，否则会返回 404。

---

## 五、环境变量

当前前端默认读取：

```text
VITE_API_BASE_URL=/api
```

对应文件：

- `.env`
- `.env.production`

如果将来网关路径变化，可以改这个变量再重新构建。

---

## 六、上线前检查清单

1. `npm run build` 是否通过
2. `dist/` 是否已部署到 Nginx `root`
3. `/api` 是否已正确反代到后端
4. `try_files $uri $uri/ /index.html;` 是否已配置
5. 上传大文件时 `client_max_body_size` 是否足够
6. 直接刷新详情页、资源页、个人中心是否正常
