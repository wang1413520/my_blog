# 经验系统后端开发文档

## 一、文档说明
### 1.1 基本信息

| 项目 | 说明 |
|------|------|
| 项目名称 | 个人博客 - 经验系统 |
| 所属后端 | Spring Boot + MyBatis + MySQL + JWT |
| 接口基础路径 | `http://localhost:8080/api` |
| 认证方式 | JWT Token（放在请求头 `Authorization` 字段） |
| 数据格式 | JSON |
| 字符编码 | UTF-8 |
| 文档版本 | v1.0 |
| 创建日期 | 2026-07-02 |

### 1.2 功能目标

为当前项目新增“用户经验条系统”，经验获取规则如下：

| 行为 | 经验值 | 说明 |
|------|------|------|
| 每天首次登录 | 10 | 同一用户同一天只发一次 |
| 成功发帖 | 5 | 帖子成功发布后发放 |
| 成功点赞 | 5 | 点赞成功后发放，重复点赞不重复发放 |
| 成功评论 | 5 | 评论成功发布后发放 |

核心要求：

- 不修改原有 `user`、`post`、`comment` 等业务表字段
- 通过新增经验表实现，不影响现有登录、帖子、评论主流程
- 前后端联调时仍沿用当前项目统一返回格式

### 1.3 统一返回格式

所有经验系统相关接口必须返回统一 JSON 格式：

```json
{
    "code": 200,
    "message": "操作成功",
    "data": {}
}
```

| 字段 | 类型 | 说明 |
|------|------|------|
| code | int | 状态码，`200` 表示成功 |
| message | string | 提示信息 |
| data | object/array/null | 返回数据 |

### 1.4 状态码说明

| 状态码 | 说明 |
|--------|------|
| 200 | 操作成功 |
| 400 | 请求参数错误 |
| 401 | 未登录或 token 过期 |
| 403 | 无权限访问 |
| 404 | 资源不存在 |
| 500 | 服务器内部错误 |

注意：

- 当前前端 `src/utils/request.js` 只将 `code === 200` 视为成功
- 因此经验查询接口、经验流水接口都必须返回 `code = 200`
- 即使“用户暂时没有经验流水”，也应返回成功结果，不要返回 `204`

## 三、数据表设计
### 3.1 `user_exp_account` - 用户经验账户表

| 字段名 | 类型 | 约束 | 说明 |
|------|------|------|------|
| id | BIGINT | PK, AUTO_INCREMENT | 主键 |
| user_id | BIGINT | NOT NULL, UNIQUE | 用户ID |
| total_exp | INT | NOT NULL DEFAULT 0 | 当前总经验 |
| created_at | DATETIME | NOT NULL DEFAULT CURRENT_TIMESTAMP | 创建时间 |
| updated_at | DATETIME | NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP | 更新时间 |

建表 SQL：

```sql
CREATE TABLE user_exp_account (
    id BIGINT PRIMARY KEY AUTO_INCREMENT COMMENT '主键ID',
    user_id BIGINT NOT NULL COMMENT '用户ID',
    total_exp INT NOT NULL DEFAULT 0 COMMENT '当前总经验',
    created_at DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP COMMENT '创建时间',
    updated_at DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP COMMENT '更新时间',
    CONSTRAINT uk_user_exp_account_user UNIQUE (user_id),
```

## 四、经验模块
### 4.1 获取当前登录用户经验信息

- **接口说明**：根据 token 获取当前登录用户经验条信息
- **请求方式**：GET
- **请求路径**：`/api/user/exp/info`
- **是否需要登录**：是

**请求头**：

| 参数名 | 类型 | 必填 | 说明 |
|--------|------|------|------|
| Authorization | string | 是 | `Bearer {token}` |

**返回字段说明**：

| 字段 | 类型 | 说明 |
|------|------|------|
| level | int | 当前等级 |
| currentExp | int | 当前总经验 |
| currentLevelNeedExp | int | 当前等级起点经验 |
| nextLevelNeedExp | int | 下一等级所需经验 |
| currentLevelProgress | int | 当前等级已获得经验 |
| currentLevelTotal | int | 当前等级总经验跨度 |
| progressPercent | int | 当前等级进度百分比 |

**返回示例**：

```json
{
    "code": 200,
    "message": "操作成功",
    "data": {
        "level": 3,
        "currentExp": 42,
        "currentLevelNeedExp": 40,
        "nextLevelNeedExp": 60,
        "currentLevelProgress": 2,
        "currentLevelTotal": 20,
        "progressPercent": 10
    }
}
```

## 五、经验发放业务规则
### 5.1 每日首次登录发经验

- **触发位置**：用户登录成功后
- **触发接口**：`POST /api/user/login`
- **奖励值**：10
- **发放规则**：同一用户同一天只发放一次

**实现建议**：

1. 用户账号密码校验成功
2. 生成 token
3. 调用经验服务 `grantDailyLoginExp(userId)`
4. 返回原登录成功结果

**去重方式**：

| 方案 | 说明 |
|------|------|
| `user_exp_daily_task` 唯一键 | 使用 `user_id + task_type + task_date` 防重复 |

注意：

- 即使经验发放失败，也建议不要阻断登录主流程
- 建议记录日志，便于后续排查

### 5.2 成功发帖发经验

- **触发位置**：帖子发布成功后
- **触发接口**：`POST /api/post/publish`
- **奖励值**：5
- **发放条件**：帖子成功入库并拿到帖子ID

**经验流水建议**：

| 字段 | 建议值 |
|------|------|
| bizType | `POST_PUBLISH` |
| bizId | 帖子ID |
| changeAmount | `5` |
| remark | `发布帖子获得经验` |

### 5.3 成功点赞发经验

- **触发位置**：帖子点赞成功后
- **触发接口**：`POST /api/post/like/{id}`
- **奖励值**：5
- **发放条件**：本次点赞必须是真正成功，不是重复点赞

**经验流水建议**：

| 字段 | 建议值 |
|------|------|
| bizType | `POST_LIKE` |
| bizId | 帖子ID |
| changeAmount | `5` |
| remark | `点赞帖子获得经验` |

注意：

- 如果当前点赞逻辑已保证“同一用户对同一帖子只能点赞一次”，则经验发放直接依赖该成功结果
- 如果点赞失败或重复点赞，不能发经验

### 5.4 成功评论发经验

- **触发位置**：评论发布成功后
- **触发接口**：`POST /api/comment/add`
- **奖励值**：5
- **发放条件**：评论成功入库并拿到评论ID

**经验流水建议**：

| 字段 | 建议值 |
|------|------|
| bizType | `POST_COMMENT` |
| bizId | 评论ID |
| changeAmount | `5` |
| remark | `发表评论获得经验` |

## 七、等级计算建议
### 7.1 第一版推荐规则

可先采用简单规则：

| 等级 | 经验区间 |
|------|------|
| Lv.1 | 0 - 19 |
| Lv.2 | 20 - 39 |
| Lv.3 | 40 - 59 |
| Lv.4 | 60 - 79 |
| Lv.5 | 80 - 99 |

简单计算方式：

```java
int level = totalExp / 20 + 1;
```

### 7.2 推荐统一封装

建议统一封装以下方法，避免前后端口径不一致：

```java
private UserExpInfoVO buildExpInfo(Integer totalExp) {
    int exp = totalExp == null ? 0 : totalExp;
    int level = exp / 20 + 1;
    int currentLevelNeedExp = (level - 1) * 20;
    int nextLevelNeedExp = level * 20;
    int currentLevelProgress = exp - currentLevelNeedExp;
    int currentLevelTotal = nextLevelNeedExp - currentLevelNeedExp;
    int progressPercent = currentLevelTotal == 0 ? 0 : currentLevelProgress * 100 / currentLevelTotal;

    UserExpInfoVO vo = new UserExpInfoVO();
    vo.setLevel(level);
    vo.setCurrentExp(exp);
    vo.setCurrentLevelNeedExp(currentLevelNeedExp);
    vo.setNextLevelNeedExp(nextLevelNeedExp);
    vo.setCurrentLevelProgress(currentLevelProgress);
    vo.setCurrentLevelTotal(currentLevelTotal);
    vo.setProgressPercent(progressPercent);
    return vo;
}
```

## 八、联调注意事项
### 8.1 与前端接口对齐要求

前端文档中的接口约定为：

| 接口 | 说明 |
|------|------|
| `GET /api/user/exp/info` | 获取经验条信息 |
| `GET /api/user/exp/records` | 获取经验流水列表 |

后端实现时请保持以下完全一致：

- 路径一致
- 返回字段名一致
- `code = 200` 成功约定一致
- 登录校验方式一致

### 8.2 空数据处理

如果用户刚注册、还没有任何经验记录：

- `GET /api/user/exp/info` 仍要返回成功
- `currentExp` 返回 `0`
- `records` 返回空数组 `[]`
- `total` 返回 `0`

错误示例：

- 返回 `404`
- 返回 `204`
- 返回 `null` 导致前端直接报错

### 8.3 时间格式建议

建议经验流水时间统一返回：

```text
yyyy-MM-dd HH:mm:ss
```

这样可以和当前项目其他模块的时间格式保持一致。

## 九、测试清单

1. 用户首次登录，当天获得 `10` 经验。
2. 同一用户当天再次登录，不重复加经验。
3. 用户第二天再次登录，再获得 `10` 经验。
4. 用户成功发帖，获得 `5` 经验。
5. 发帖失败时，不增加经验。
6. 用户首次点赞某帖子，获得 `5` 经验。
7. 重复点赞同一帖子，不重复加经验。
8. 用户成功评论，获得 `5` 经验。
9. 评论失败时，不增加经验。
10. 查询经验信息接口返回字段与前端文档完全一致。
11. 查询经验流水接口空数据时，仍返回 `code = 200`。

## 十一、推荐开发顺序

1. 新建 `user_exp_account`、`user_exp_record`、`user_exp_daily_task` 三张表。
2. 新增实体类、VO、Mapper。

5. 再实现 `GET /api/user/exp/records`。
6. 最后接入登录、发帖、点赞、评论成功后的经验发放逻辑。
