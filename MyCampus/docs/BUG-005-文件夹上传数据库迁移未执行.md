# BUG-005：文件夹上传接口报错 Table 'resource_upload_batch' doesn't exist

## 基本信息

| 项目 | 内容 |
|------|------|
| Bug 编号 | BUG-005 |
| 发现日期 | 2026-06-26 |
| 严重程度 | 🔴 高（功能完全不可用） |
| 影响范围 | `POST /api/resource/upload/folder` 接口 |
| 触发条件 | 新增代码部署后，未执行数据库迁移脚本即调用接口 |
| 修复状态 | ✅ 已修复 |

## 现象

调用 `POST /api/resource/upload/folder` 接口时，服务器返回 500 错误，控制台抛出异常：

```
java.sql.SQLSyntaxErrorException: Table 'my_web_school_project.resource_upload_batch' doesn't exist
```

完整堆栈：

```text
org.springframework.jdbc.BadSqlGrammarException: 
### Error querying database.  Cause: java.sql.SQLSyntaxErrorException: 
    Table 'my_web_school_project.resource_upload_batch' doesn't exist
### The error may exist in file [ResourceUploadBatchMapper.xml]
### SQL: SELECT MAX(batch_no) FROM resource_upload_batch 
         WHERE batch_no LIKE CONCAT(?, '%')
```

## 根因分析

本次开发新增了：
1. **新表** `resource_upload_batch` — 文件夹上传批次表
2. **旧表扩展** `resource` 表新增 4 个字段（`upload_type`、`batch_no`、`folder_name`、`relative_path`）

但代码部署后，**未同步执行数据库迁移脚本** `migration-folder-upload.sql`，导致：

- `ResourceUploadBatchMapper.xml` 中的 `SELECT MAX(batch_no) ...` 查询找不到 `resource_upload_batch` 表
- `ResourceMapper.xml` 中的 `INSERT INTO resource(... upload_type, batch_no ...)` 会因为缺少字段而报错（如果先修了上一个错误的话）

### 调用链

```text
POST /api/resource/upload/folder
  → ResourceController.uploadFolder()
    → ResourceServiceImpl.uploadFolder()
      → generateBatchNo()
        → ResourceUploadBatchMapper.selectMaxBatchNoForToday()
          → ❌ Table 'resource_upload_batch' doesn't exist
```

## 修复方案

执行迁移脚本：

```bash
mysql -u root -p my_web_school_project < src/main/resources/migration-folder-upload.sql
```

该脚本包含：

```sql
-- 1. 扩展 resource 表
ALTER TABLE resource
    ADD COLUMN upload_type VARCHAR(20) NOT NULL DEFAULT 'single',
    ADD COLUMN batch_no VARCHAR(32) DEFAULT NULL,
    ADD COLUMN folder_name VARCHAR(255) DEFAULT NULL,
    ADD COLUMN relative_path VARCHAR(500) DEFAULT NULL;
CREATE INDEX idx_resource_batch_no ON resource(batch_no);

-- 2. 创建 resource_upload_batch 表
CREATE TABLE IF NOT EXISTS resource_upload_batch (
    id BIGINT PRIMARY KEY AUTO_INCREMENT,
    batch_no VARCHAR(32) NOT NULL,
    user_id BIGINT NOT NULL,
    folder_name VARCHAR(255) NOT NULL,
    ...
);
```

## 验证结果

执行迁移后，验证通过：

```sql
-- 确认 resource 表有新字段
SHOW COLUMNS FROM resource LIKE 'upload_type';
-- ✅ upload_type | varchar(20) | NO | single

SHOW COLUMNS FROM resource LIKE 'batch_no';
-- ✅ batch_no | varchar(32) | YES | NULL

-- 确认批次表已创建
SHOW TABLES LIKE 'resource_upload_batch';
-- ✅ resource_upload_batch
```

接口恢复正常，文件夹上传功能可正常使用。

## 经验教训

### 1. 数据库迁移应与代码部署同步

| 错误做法 | 正确做法 |
|----------|----------|
| 先部署代码，再想起来执行迁移 | 部署代码的同时执行迁移脚本 |
| 手动执行 SQL | 使用 Flyway / Liquibase 等迁移工具管理版本 |

### 2. 建议引入 Flyway

当前项目没有数据库版本管理工具，迁移全靠人工执行，容易遗漏。建议后续引入 Flyway：

```xml
<!-- pom.xml -->
<dependency>
    <groupId>org.flywaydb</groupId>
    <artifactId>flyway-mysql</artifactId>
</dependency>
```

```yaml
# application.yml
spring:
  flyway:
    enabled: true
    locations: classpath:db/migration
```

将 `migration-folder-upload.sql` 重命名为 `V2__add_folder_upload.sql` 放入 `db/migration/` 目录，应用启动时自动执行。

### 3. 建议使用健康检查

可以在应用启动时检查关键表是否存在，提前发现问题：

```java
@Component
public class DatabaseHealthCheck {
    @Autowired
    private DataSource dataSource;
    
    @EventListener(ApplicationReadyEvent.class)
    public void checkRequiredTables() {
        // 检查 resource_upload_batch 是否存在
        // 检查 resource 表是否有所需字段
        // 不存在则记录 ERROR 日志
    }
}
```
