# 备忘录模块开发教程

## 一、概述

本文档记录了个人博客后端项目中"备忘录（Memo）"模块的完整开发过程，包括数据库设计、后端代码实现、接口联调说明。

### 1.1 技术栈

| 层级 | 技术 |
|------|------|
| 框架 | Spring Boot 3.5.14 |
| ORM | MyBatis 3 + XML Mapper |
| 数据库 | MySQL 8.0 |
| 参数校验 | Jakarta Bean Validation |
| 简化代码 | Lombok |

### 1.2 模块定位

备忘录是一个**独立模块**，不复用 `post` 表。原因是：

1. 语义不同——备忘录不是文章
2. 操作频率不同——更轻、更碎片化
3. 状态字段需求不同——需要完成状态、置顶状态
4. 后续扩展方便——搜索、归档、提醒等

## 二、数据库设计

### 2.1 建表 SQL

文件位置：`docs/memo.sql`

```sql
CREATE TABLE IF NOT EXISTS memo (
    id BIGINT NOT NULL AUTO_INCREMENT COMMENT '主键ID',
    user_id BIGINT NOT NULL COMMENT '所属用户ID',
    content VARCHAR(120) NOT NULL COMMENT '备忘录内容',
    status TINYINT NOT NULL DEFAULT 0 COMMENT '状态 0未完成 1已完成',
    is_pinned TINYINT NOT NULL DEFAULT 0 COMMENT '置顶 0否 1是',
    create_time DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP COMMENT '创建时间',
    update_time DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP COMMENT '更新时间',
    PRIMARY KEY (id),
    KEY idx_memo_user_id (user_id),
    KEY idx_memo_user_status_pin_update (user_id, is_pinned, status, update_time)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='用户备忘录表';
```

### 2.2 执行方式

在 MySQL 中执行：

```bash
mysql -u root -p your_database < docs/memo.sql
```

或登录 MySQL 后：

```sql
source docs/memo.sql;
```

### 2.3 字段说明

| 字段 | 类型 | 说明 |
|------|------|------|
| `id` | `BIGINT` | 主键，自增 |
| `user_id` | `BIGINT` | 所属用户ID，所有操作必须带此条件 |
| `content` | `VARCHAR(120)` | 备忘录内容，最长120字符 |
| `status` | `TINYINT` | 完成状态：`0`未完成 / `1`已完成 |
| `is_pinned` | `TINYINT` | 置顶状态：`0`否 / `1`是 |
| `create_time` | `DATETIME` | 创建时间，默认当前时间 |
| `update_time` | `DATETIME` | 更新时间，自动更新 |

## 四、各层代码详解

### 4.1 实体类 Memo.java

```java
@Data
public class Memo {
    private Long id;
    private Long userId;
    private String content;
    private Integer status;     // 0-未完成，1-已完成
    private Integer isPinned;   // 0-未置顶，1-已置顶
    private LocalDateTime createTime;
    private LocalDateTime updateTime;
}
```

数据库中的 `DATETIME` 自动映射到 Java 的 `LocalDateTime`。

### 4.2 DTO 层

四个 DTO 都使用 Jakarta Bean Validation 注解进行参数校验：

| DTO | 核心校验 |
|-----|----------|
| `AddMemoDTO` | `@NotBlank` + `@Size(max=120)` |
| `UpdateMemoDTO` | `@NotBlank` + `@Size(max=120)` |
| `UpdateMemoStatusDTO` | `@NotNull` + `@Min(0)` + `@Max(1)` |
| `UpdateMemoPinDTO` | `@NotNull` + `@Min(0)` + `@Max(1)` |

校验失败时，`GlobalExceptionHandler` 自动捕获并返回 `code: 400` + 第一条校验错误消息。

### 4.3 VO 层 MemoVO.java

```java
@Data
public class MemoVO {
    private Long id;
    private String content;
    private Integer status;
    private Integer isPinned;
    private Long createTime;    // 13位毫秒时间戳
    private Long updateTime;    // 13位毫秒时间戳
}
```

**关键设计决策：时间字段使用 `Long` 类型（13位毫秒时间戳），而非 `String`。**

原因：
1. 前端当前按时间戳处理（`formatTime(new Date(timestamp))`）
2. 避免不同浏览器对日期字符串解析不一致

转换代码在 `MemoServiceImpl.toMemoVO()` 中：

```java
vo.setCreateTime(memo.getCreateTime()
        .atZone(ZoneId.systemDefault())
        .toInstant()
        .toEpochMilli());
```

### 4.4 Mapper 层

**MemoMapper.java** — 接口定义了 6 个数据操作方法：

| 方法 | 说明 |
|------|------|
| `selectListByUserId` | 查询用户所有备忘录 |
| `selectByIdAndUserId` | 按ID+用户ID查单条 |
| `insertMemo` | 新增（useGeneratedKeys） |
| `updateContent` | 修改内容 |
| `updateStatus` | 切换完成状态 |
| `updatePinned` | 切换置顶状态 |
| `deleteByIdAndUserId` | 删除 |

**MemoMapper.xml** — 所有 SQL 都带 `user_id = #{userId}` 条件，确保数据隔离。

列表查询的排序逻辑：

```sql
ORDER BY is_pinned DESC, status ASC, update_time DESC
```

即：置顶优先 → 未完成优先 → 最近更新优先。

### 4.5 Service 层

**MemoService.java** — 接口定义：

| 方法 | 说明 |
|------|------|
| `getMemoList()` | 获取列表 |
| `addMemo(AddMemoDTO)` | 新增 |
| `updateMemo(Long, UpdateMemoDTO)` | 修改内容 |
| `updateStatus(Long, UpdateMemoStatusDTO)` | 切换状态 |
| `updatePinned(Long, UpdateMemoPinDTO)` | 切换置顶 |
| `deleteMemo(Long)` | 删除 |

**MemoServiceImpl.java** — 实现要点：

1. **用户隔离**：所有操作通过 `UserContext.getUserId()` 获取当前用户ID
2. **新增默认值**：`status=0`、`isPinned=0`
3. **影响行数校验**：更新/删除影响行数为 0 时抛出 `404` 异常
4. **时间转换**：`LocalDateTime` → 13位毫秒时间戳

### 4.6 Controller 层

**MemoController.java** — 6 个 REST 接口：

| 方法 | 路径 | 说明 |
|------|------|------|
| `GET` | `/api/memo/list` | 获取列表 |
| `POST` | `/api/memo/add` | 新增 |
| `PUT` | `/api/memo/{id}` | 修改内容 |
| `PUT` | `/api/memo/{id}/status` | 切换完成状态 |
| `PUT` | `/api/memo/{id}/pin` | 切换置顶状态 |
| `DELETE` | `/api/memo/{id}` | 删除 |

**关键设计：**

- 所有接口都加了 `@RequireLogin` 注解，拦截器自动校验登录态
- `userId` 从 Token 中解析，**不从前端请求体获取**
- 返回格式统一为 `Result<T>`：`{ code: 200, message: "...", data: {...} }`

## 五、安全设计

### 5.1 用户隔离

所有 SQL 操作都带 `user_id = #{userId}` 条件，确保用户 A 无法操作用户 B 的数据。

### 5.2 userId 来源

`userId` **只从 Token 中解析**（`UserContext.getUserId()`），不允许从前端请求体传入。

### 5.3 鉴权流程

```
前端请求 → LoginInterceptor.preHandle()
         → 检查 @RequireLogin 注解
         → 解析 Authorization Header 中的 Token
         → 存入 UserContext (ThreadLocal)
         → 请求结束后清除
```

### 5.4 异常处理

| 场景 | HTTP状态码 | 业务code | 说明 |
|------|-----------|----------|------|
| 未登录 | 401 | 401 | 拦截器直接返回 |
| 记录不存在/无权限 | 200 | 404 | 业务异常 |
| 参数校验失败 | 200 | 400 | @Valid 触发 |
| 其他业务异常 | 200 | 非200 | BaseException |

## 七、联调验收清单

开发完成后，至少验证以下场景：

- [ ] 登录用户能看到自己的备忘录列表
- [ ] 置顶的备忘录排在前面
- [ ] 未完成的排在已完成前面
- [ ] 用户 A 看不到用户 B 的备忘录
- [ ] 新增备忘录成功，空内容被拦截
- [ ] 内容超过 120 字符被拦截
- [ ] 能切换完成/未完成状态
- [ ] 能切换置顶/取消置顶
- [ ] 删除后列表中不再出现该记录
- [ ] `createTime` / `updateTime` 为 13 位毫秒时间戳
- [ ] 修改后 `updateTime` 会更新
- [ ] `status` / `isPinned` 返回数字 0/1（不是布尔值）
- [ ] Token 失效时返回 401

## 八、与前端对齐的关键约定

为确保前后端联调不出问题，后端严格遵守以下约定：

1. **字段名**：`id` / `content` / `status` / `isPinned` / `createTime` / `updateTime`
2. **状态值**：`status` 和 `isPinned` 都是数字 `0` / `1`，不是 `true` / `false`
3. **时间格式**：`createTime` 和 `updateTime` 都是 13 位毫秒时间戳（`Long`）
4. **不暴露 userId**：返回数据中不包含 `userId` 字段
5. **userId 不来自前端**：归属从 Token 解析，不信任前端传入
