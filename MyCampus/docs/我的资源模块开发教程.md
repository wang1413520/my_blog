# 我的资源模块开发教程

## 一、概述

本文档记录了个人博客后端项目中"我的资源（My Resource）"模块的完整开发过程，包括需求分析、代码实现、接口联调说明。

### 1.1 技术栈

| 层级 | 技术 |
|------|------|
| 框架 | Spring Boot 3.5.14 |
| ORM | MyBatis 3 + XML Mapper |
| 分页 | PageHelper |
| 数据库 | MySQL 8.0 |
| 认证 | JWT + LoginInterceptor |

### 1.2 模块定位

"我的资源"是个人中心的资源管理模块，用于查询**当前登录用户**上传的所有资料。

### 1.3 与公共资源列表的区别

| 维度 | 公共资源列表 | 我的资源 |
|------|-------------|---------|
| 接口 | `GET /api/resource/list` | `GET /api/resource/my/list` |
| 鉴权 | 无需登录 | 必须登录 |
| 数据范围 | 全部用户 | 仅当前用户 |
| 筛选维度 | `fileType`、`keyword` | `fileType`、`keyword`、`uploadType` |

---

## 二、设计决策

### 2.1 为什么不复用公共列表接口

文档指出不建议在公共接口上加 `mine=true` 参数：

1. 公共列表匿名可访问，"我的资源"必须登录
2. 将公开列表和个人列表拆开，职责更清晰
3. 利于后续扩展"我的资源统计""我的上传批次"等能力

### 2.2 是否需要新建表

**不需要。** 数据已存在于 `resource` 表中，"我的资源"只是按 `user_id` 做一次筛选。

### 2.3 复用现有能力

| 接口 | 用途 | 处理方式 |
|------|------|---------|
| `GET /api/resource/list` | 公共资源列表 | 保持不变 |
| `DELETE /api/resource/{id}` | 删除资源 | 直接复用（权限已校验上传者） |
| `GET /api/resource/download/{id}` | 下载资源 | 直接复用 |
| `GET /api/resource/{id}` | 资源详情 | 直接复用 |
| `POST /api/resource/upload` | 上传资源 | 保持不变 |
| `POST /api/resource/upload/folder` | 文件夹上传 | 保持不变 |

## 五、各层代码详解

### 5.1 DTO 层 — ResourceMyListQueryDTO

```java
@Data
public class ResourceMyListQueryDTO {
    private Integer page;       // 页码，默认 1
    private Integer size;       // 每页大小，默认 10
    private String keyword;     // 标题/描述关键字
    private String fileType;    // 文件类型：pdf / doc / docx
    private String uploadType;  // 上传类型：single / folder
}
```

### 5.2 Mapper 层

**ResourceMapper.java** 新增方法：

```java
List<ResourceItemVO> selectMyResourceList(
    @Param("userId") Long userId,
    @Param("keyword") String keyword,
    @Param("fileType") String fileType,
    @Param("uploadType") String uploadType);
```

**ResourceMapper.xml** 新增 SQL：

```xml
<select id="selectMyResourceList" resultType="com.wang.mycampus.vo.ResourceItemVO">
    SELECT r.id, r.title, r.description, r.file_type, r.file_size,
           r.download_count, r.upload_type, r.folder_name,
           r.relative_path, r.batch_no, r.create_time,
           COALESCE(u.nickname, u.username) AS uploaderName
    FROM resource r
    LEFT JOIN user u ON r.user_id = u.id
    <where>
        r.user_id = #{userId}
        <if test="keyword != null and keyword != ''">
            AND (r.title LIKE CONCAT('%', #{keyword}, '%')
                 OR r.description LIKE CONCAT('%', #{keyword}, '%'))
        </if>
        <if test="fileType != null and fileType != ''">
            AND r.file_type = #{fileType}
        </if>
        <if test="uploadType != null and uploadType != ''">
            AND r.upload_type = #{uploadType}
        </if>
    </where>
    ORDER BY r.create_time DESC, r.id DESC
</select>
```

**关键设计：**

| 设计点 | 说明 |
|--------|------|
| 核心条件 | `r.user_id = #{userId}` — 强制过滤当前用户 |
| 关键字搜索 | 同时匹配 `title` 和 `description` |
| 上传类型筛选 | 支持 `single` / `folder` |
| 文件类型筛选 | 复用公共列表逻辑 |
| 排序 | `create_time DESC, id DESC` — 最新上传的在前 |
| uploaderName | 使用 `COALESCE(nickname, username)` 兜底 |

### 5.3 Service 层

**ResourceService.java** 新增方法签名：

```java
PageVO<ResourceItemVO> getMyResourceList(Long userId, String fileType, String keyword,
                                         String uploadType, Integer page, Integer size);
```

**ResourceServiceImpl.java** 实现要点：

```java
@Override
public PageVO<ResourceItemVO> getMyResourceList(Long userId, String fileType, String keyword,
                                                 String uploadType, Integer page, Integer size) {
    // 1. 分页参数兜底
    if (page == null || page < 1) page = 1;
    if (size == null || size < 1) size = 10;
    if (size > 50) size = 50;  // 最大每页 50 条

    // 2. 枚举字段校验
    if (fileType != null && !List.of("pdf", "doc", "docx").contains(fileType.trim())) {
        throw new BaseException(400, "文件类型参数不合法");
    }
    if (uploadType != null && !List.of("single", "folder").contains(uploadType.trim())) {
        throw new BaseException(400, "上传类型参数不合法");
    }

    // 3. 使用 PageHelper 分页
    Page<Object> objects = PageHelper.startPage(page, size);
    List<ResourceItemVO> resourceList = resourceMapper.selectMyResourceList(
            userId, keyword, fileType, uploadType);

    // 4. 组装 PageVO
    PageVO<ResourceItemVO> pageVO = new PageVO<>();
    pageVO.setRecords(resourceList);
    pageVO.setTotal((int) objects.getTotal());
    pageVO.setPage(page);
    pageVO.setSize(size);
    return pageVO;
}
```

**Service 层职责：**
- 分页参数兜底（`page < 1` → 1，`size > 50` → 50）
- 枚举字段白名单校验（`fileType`、`uploadType`）
- 调用 Mapper + PageHelper
- 返回标准 `PageVO<ResourceItemVO>`

### 5.4 Controller 层

在 `ResourceController` 中新增一个端点：

```java
@RequireLogin
@GetMapping("/api/resource/my/list")
public Result<PageVO<ResourceItemVO>> getMyResourceList(
        @RequestParam(required = false) String fileType,
        @RequestParam(required = false) String keyword,
        @RequestParam(required = false) String uploadType,
        @RequestParam(defaultValue = "1") Integer page,
        @RequestParam(defaultValue = "10") Integer size) {

    Long userId = UserContext.getUserId();
    log.info("获取我的资源列表 userId={}, fileType={}, keyword={}, uploadType={}",
            userId, fileType, keyword, uploadType);

    PageVO<ResourceItemVO> pageVO = resourceService.getMyResourceList(
            userId, fileType, keyword, uploadType, page, size);
    return Result.success(pageVO);
}
```

**与公共列表接口的对比：**

```java
// 公共列表 — 无需登录
GET /api/resource/list?fileType=&keyword=&page=1&size=10

// 我的资源 — 必须登录，自动按当前用户过滤
GET /api/resource/my/list?fileType=&keyword=&uploadType=&page=1&size=10
```

## 八、与删除接口的配合

"我的资源"页面删除资源时直接复用现有接口：

```http
DELETE /api/resource/{id}
Authorization: Bearer <token>
```

**权限校验逻辑（已存在于 `ResourceServiceImpl.deleteResource`）：**

```
1. 查询资源是否存在 → 不存在返回 404
2. 查询当前用户角色 → 管理员直接放行
3. 资源上传者 = 当前用户 → 放行
4. 都不是 → 返回 403 无权删除
```

前端"我的资源"页面无需任何额外处理，直接调用现有删除接口即可。

## 九、安全设计

### 9.1 userId 来源

```
userId = UserContext.getUserId()
       = LoginInterceptor 从 Token 解析
       ≠ 前端请求参数传入
```

### 9.2 数据隔离

核心 SQL 条件：`WHERE r.user_id = #{userId}`

无论如何传参，绝不可能看到别人的资源。

### 9.3 鉴权覆盖

| 场景 | 返回 |
|------|------|
| 未登录 | `401` + "请先登录"（拦截器处理） |
| 已登录 | 仅返回当前用户的资源 |
| 传别人的 userId | ❌ 不可行（Controller 不接收此参数） |

## 十、联调验收清单

- [ ] 未登录访问 `/api/resource/my/list` 返回 `401`
- [ ] 登录后只返回当前用户自己的资源
- [ ] 用户 A 看不到用户 B 的资源
- [ ] 空列表返回 `code = 200`（不返回 404）
- [ ] 关键字筛选正常（标题 + 描述）
- [ ] 文件类型筛选正常（`pdf` / `doc` / `docx`）
- [ ] 上传类型筛选正常（`single` / `folder`）
- [ ] 文件夹上传资源带回 `uploadType` / `folderName` / `relativePath` / `batchNo`
- [ ] 分页参数正常（默认 page=1, size=10）
- [ ] `size` 超过 50 时自动截断为 50
- [ ] 非法 `fileType`（如 `exe`）返回 400
- [ ] 非法 `uploadType`（如 `batch`）返回 400
- [ ] 删除接口在"我的资源"场景下仍可正常使用（上传者本人可删）
