## 1. 背景与需求分析

### 1.1 需求描述

为用户系统开发头像上传功能，用户登录后可以上传一张图片作为头像，系统将图片存储到阿里云 OSS，并返回可访问的 URL 保存到数据库。

### 1.2 接口规格

| 项目 | 说明 |
|------|------|
| **接口路径** | `POST /api/user/avatar` |
| **请求方式** | POST |
| **是否需要登录** | 是（JWT Token） |
| **Content-Type** | `multipart/form-data` |

**请求参数：**

| 参数名 | 类型 | 必填 | 说明 |
|--------|------|------|------|
| file | file | 是 | 头像图片文件，支持 jpg/png/webp，最大 5MB |

**成功响应：**

```json
{
    "code": 200,
    "message": "操作成功",
    "data": "https://wang-java-ai.oss-cn-beijing.aliyuncs.com/avatar/user_1_a1b2c3d4e5f6.jpg"
}
```

**错误响应：**

```json
{
    "code": 400,
    "message": "仅支持 jpg/png/webp 格式的头像图片"
}
```

### 1.3 涉及的技术栈

- **Spring Boot 3.x**：Web 框架
- **MyBatis**：ORM 数据库操作
- **阿里云 OSS**：对象存储（文件上传）
- **JWT**：用户身份认证
- **Lombok**：简化 Java 代码

## 2. 项目架构概览

本项目采用经典的分层架构：

```
┌─────────────────────────────────────┐
│  Controller 层（接收请求、参数校验）   │
├─────────────────────────────────────┤
│  Service 层（业务逻辑）               │
├─────────────────────────────────────┤
│  Mapper 层（数据访问、SQL）           │
├─────────────────────────────────────┤
│  Database（MySQL）                   │
└─────────────────────────────────────┘
```

**调用链路：**

```
HTTP Request
  → LoginInterceptor（解析 JWT，注入 UserContext）
    → Controller（@RequireLogin，获取 userId）
      → Service.uploadAvatar(userId, file)
        → 校验文件 → 上传 OSS → Mapper.updateAvatar()
          → 返回 avatarUrl
```

## 3. 开发步骤

### 3.1 确认实体与数据库字段

首先确认 `User` 实体中是否有存储头像的字段。本项目 `User` 实体如下：

```java
// pojo/User.java
@Data
public class User {
    private Long id;
    private String username;
    private String password;
    private String nickname;
    private String avatar;      // ← 头像 URL 存储字段
    private Integer role;        // 0-普通用户，1-管理员
    private LocalDateTime createTime;
    private LocalDateTime updateTime;
}
```

> **注意**：如果数据库表缺少 `avatar` 字段，需要先执行 `ALTER TABLE user ADD COLUMN avatar VARCHAR(500);`。

---

### 3.2 Mapper 层：编写数据访问方法

Mapper 层负责与数据库交互。我们需要一个 **只更新 avatar 字段** 的方法。

#### 3.2.1 Mapper 接口

```java
// mapper/UserMapper.java
@Mapper
public interface UserMapper {

    // ... 其他已有方法 ...

    /*
    * 更新用户头像
    * */
    @Update("update user set avatar = #{avatar} where id = #{userId}")
    void updateAvatar(@Param("userId") Long userId, @Param("avatar") String avatar);
}
```

> **开发要点**：
> - 使用 `@Update` 注解编写 SQL，简单直观
> - 使用 `@Param` 注解绑定参数名，防止 MyBatis 参数映射失败
> - 仅更新 `avatar` 字段，避免影响其他字段

---

### 3.3 Service 层：编写业务逻辑接口与实现

Service 层是核心业务逻辑所在，负责 **校验 → 上传 → 存储 → 返回** 的完整流程。

#### 3.3.1 Service 接口

```java
// service/UserService.java
public interface UserService {

    // ... 其他已有方法 ...

    // 上传用户头像
    String uploadAvatar(Long userId, MultipartFile file);
}
```

#### 3.3.2 Service 实现（关键代码）

```java
// service/Impl/UserServiceImpl.java
@Service
public class UserServiceImpl implements UserService {

    @Autowired
    private UserMapper userMapper;

    @Autowired
    private OSS ossClient;          // 阿里云 OSS 客户端

    @Autowired
    private OssConfig ossConfig;    // OSS 配置（bucket, endpoint 等）

    @Override
    public String uploadAvatar(Long userId, MultipartFile file) {
        // ========== 步骤 1：校验文件是否为空 ==========
        if (file == null || file.isEmpty()) {
            throw new BaseException(400, "请选择要上传的头像图片");
        }

        // ========== 步骤 2：提取并校验文件类型 ==========
        String originalFilename = file.getOriginalFilename();
        String ext = "";
        if (originalFilename != null && originalFilename.contains(".")) {
            ext = originalFilename.substring(originalFilename.lastIndexOf(".")).toLowerCase();
        }
        String fileType = ext.replace(".", "");
        if (!List.of("jpg", "jpeg", "png", "webp").contains(fileType)) {
            throw new BaseException(400, "仅支持 jpg/png/webp 格式的头像图片");
        }

        // ========== 步骤 3：校验文件大小 ==========
        long fileSize = file.getSize();
        if (fileSize > 5 * 1024 * 1024) {   // 5MB = 5 * 1024 * 1024 bytes
            throw new BaseException(400, "头像图片大小不能超过 5MB");
        }

        // ========== 步骤 4：生成唯一文件名 ==========
        String objectName = "avatar/user_" + userId + "_" + UUID.randomUUID().toString().replace("-", "") + ext;

        // ========== 步骤 5：上传到阿里云 OSS ==========
        try (InputStream inputStream = file.getInputStream()) {
            ossClient.putObject(ossConfig.getBucketName(), objectName, inputStream);
        } catch (Exception e) {
            log.error("OSS 头像上传失败", e);
            throw new BaseException(500, "头像上传失败，请稍后重试");
        }

        // ========== 步骤 6：构造可访问的 URL ==========
        String endpoint = ossConfig.getEndpoint();  // 例如：https://oss-cn-beijing.aliyuncs.com
        String host = endpoint.replace("https://", "").replace("http://", "");
        String avatarUrl = "https://" + ossConfig.getBucketName() + "." + host + "/" + objectName;
        // 结果示例：https://wang-java-ai.oss-cn-beijing.aliyuncs.com/avatar/user_1_abc123.jpg

        // ========== 步骤 7：更新数据库 ==========
        userMapper.updateAvatar(userId, avatarUrl);

        log.info("用户 {} 头像上传成功: {}", userId, avatarUrl);
        return avatarUrl;
    }
}
```

> **开发要点逐行解析**：

| 步骤 | 关键代码 | 说明 |
|------|---------|------|
| 校验空文件 | `file.isEmpty()` | 防止用户未选择文件就提交 |
| 提取扩展名 | `lastIndexOf(".")` → `substring` | 安全获取文件后缀，注意处理无后缀的情况 |
| 白名单校验 | `List.of("jpg", "jpeg", "png", "webp")` | **白名单优于黑名单**，防止上传恶意文件 |
| 大小校验 | `5 * 1024 * 1024` | 先算好，代码自解释，不用写 `5242880` |
| 生成路径 | `avatar/user_{id}_{uuid}` | 按用户 ID 分目录，UUID 防重名 |
| try-with-resources | `try (InputStream ...)` | 自动关闭流，防止资源泄漏 |
| 构造 URL | `bucketName.endpoint/objectName` | OSS 公开访问 URL 的标准格式 |
| 更新 DB | `userMapper.updateAvatar()` | 上传成功后才写数据库 |

### 3.4 Controller 层：暴露 REST 接口

Controller 层负责接收 HTTP 请求，调用 Service，返回统一格式的响应。

```java
// controller/UserController.java
@Slf4j
@RestController()
@RequestMapping("")
public class UserController {

    @Autowired
    private UserService userService;

    /*
    * 头像上传接口
    * */
    @RequireLogin                                           // ← ① 登录拦截
    @PostMapping("/api/user/avatar")                         // ← ② 路径映射
    public Result<String> uploadAvatar(
            @RequestParam("file") MultipartFile file) {      // ← ③ 接收文件
        Long userId = UserContext.getUserId();               // ← ④ 获取当前用户
        log.info("用户 {} 正在上传头像, 文件名: {}", userId, file.getOriginalFilename());
        String avatarUrl = userService.uploadAvatar(userId, file);
        return Result.success(avatarUrl);                    // ← ⑤ 返回统一格式
    }
}
```

> **开发要点逐行解析**：

| 行号 | 关键代码 | 说明 |
|------|---------|------|
| ① | `@RequireLogin` | 自定义注解，由 `LoginInterceptor` 拦截验证 JWT Token |
| ② | `@PostMapping("/api/user/avatar")` | RESTful 风格，POST 表示创建/上传操作 |
| ③ | `@RequestParam("file")` | 接收 `multipart/form-data` 中的文件字段，参数名 `file` |
| ④ | `UserContext.getUserId()` | 从 ThreadLocal 获取当前登录用户 ID（由拦截器注入） |
| ⑤ | `Result.success(avatarUrl)` | 统一响应格式 `{code: 200, message: "操作成功", data: "https://..."}` |

### 3.5 配置拦截器放行（如需要）

本项目拦截器配置在 `WenConfig.java` 中：

```java
// config/WenConfig.java
@Override
public void addInterceptors(InterceptorRegistry registry) {
    registry.addInterceptor(loginInterceptor)
        .addPathPatterns("/api/**")            // 拦截所有 /api/ 开头的请求
        .excludePathPatterns(
            "/api/user/login",                 // 登录接口不拦截
            "/api/user/register"               // 注册接口不拦截
        );
}
```

由于 `/api/user/avatar` 使用了 `@RequireLogin` 注解，`LoginInterceptor` 会根据注解决定是否拦截，**无需额外配置**。

## 6. 常见问题与最佳实践

### 6.1 为什么使用白名单校验文件类型？

```java
// ✅ 推荐：白名单（只允许已知的安全类型）
if (!List.of("jpg", "jpeg", "png", "webp").contains(fileType)) {
    throw new BaseException(400, "仅支持 jpg/png/webp 格式的头像图片");
}

// ❌ 不推荐：黑名单（攻击者总能找到新后缀绕过）
if (List.of("exe", "sh", "jsp").contains(fileType)) {
    throw new BaseException(400, "不支持的文件类型");
}
```

**原则**：只允许已知安全的类型，拒绝一切未知类型。

### 6.2 为什么文件名要用 UUID？

```java
// ✅ 推荐：UUID 防重名 + 用户 ID 分类
"avatar/user_" + userId + "_" + UUID.randomUUID() + ext
// 结果：avatar/user_1_a1b2c3d4e5f6.jpg

// ❌ 不推荐：直接使用原始文件名（可能重名、含特殊字符）
"avatar/" + originalFilename
// 风险：用户A上传 头像.jpg，用户B也上传 头像.jpg → 覆盖
```

### 6.3 异常处理策略

```java
// 业务异常使用 BaseException，会被 GlobalExceptionHandler 统一拦截
throw new BaseException(400, "仅支持 jpg/png/webp 格式的头像图片");

// 返回统一格式：{"code":400,"message":"仅支持 jpg/png/webp 格式的头像图片"}

// 系统异常（如 OSS 网络问题）捕获后包装为 BaseException
try {
    ossClient.putObject(...);
} catch (Exception e) {
    log.error("OSS 上传失败", e);       // 服务端记录完整日志
    throw new BaseException(500, "头像上传失败，请稍后重试");  // 给用户友好提示
}
```

> **原则**：给用户看友好的提示，给开发者看完整的堆栈（通过日志）。

### 6.4 如何扩展：从本地存储迁移到 OSS？

如果你当前使用本地存储，迁移到 OSS 只需修改 Service 层：

```java
// 本地存储版本
String savePath = "/uploads/avatar/" + objectName;
file.transferTo(new File(savePath));
String avatarUrl = "/uploads/avatar/" + objectName;

// OSS 存储版本（只改这里）
try (InputStream inputStream = file.getInputStream()) {
    ossClient.putObject(bucketName, objectName, inputStream);
}
String avatarUrl = "https://" + bucketName + "." + host + "/" + objectName;
```

Controller 层和 Mapper 层完全不变 —— 这就是分层架构的好处。

### 6.5 安全性检查清单

- [x] 登录认证：`@RequireLogin` 确保只有登录用户能上传
- [x] 用户隔离：只能修改自己的头像（`userId` 来自 `UserContext`，无法伪造）
- [x] 文件类型白名单：仅允许图片格式
- [x] 文件大小限制：防止上传超大文件耗尽服务器资源
- [x] 异常统一处理：不暴露内部错误细节给客户端

## 附录：接口开发通用步骤模板

按照以下步骤可以快速开发任意业务接口：

```
1. 明确需求
   ├── 请求路径、方式、参数
   ├── 是否需要登录
   └── 返回数据格式

2. 实体与 DTO/VO
   ├── 确认数据库表结构
   ├── 如有需要，创建新的 DTO（接收参数）或 VO（返回数据）
   └── 必要时执行 DDL 变更

3. Mapper 层
   ├── 在 Mapper 接口中新增方法
   └── 编写 SQL（注解或 XML）

4. Service 层
   ├── 在 Service 接口中新增方法签名
   └── 在 ServiceImpl 中实现业务逻辑
       ├── 参数校验
       ├── 业务处理
       ├── 调用 Mapper
       └── 异常处理

5. Controller 层
   ├── 新增端点方法
   ├── 添加 @RequireLogin（如需要登录）
   └── 调用 Service 并返回 Result

6. 测试验证
   ├── 正常流程测试
   └── 异常场景测试
```
