# Bug 记录：IntelliJ IDEA 连接 MySQL 报 Connection Refused

**日期**：2026-06-14  
**严重程度**：高（开发环境数据库不可用）  
**状态**：已修复  

---

## 现象

在 IntelliJ IDEA 中连接本地 MySQL 数据库时，抛出以下异常：

```
java.net.ConnectException: Connection refused: connect
    at java.base/sun.nio.ch.Net.connect0(Native Method)
    at java.base/sun.nio.ch.Net.connect(Net.java:546)
    ...
    at com.mysql.cj.jdbc.NonRegisteringDriver.connect(NonRegisteringDriver.java:189)
```

端口 3306 无任何进程监听，MySQL 服务状态显示为 `Stopped`。

---

## 触发条件

2026年6月13日 22:42，Windows Update 自动安装了安全更新 **KB5094126**（Security Update），该更新将系统中的 `MSVCP140.dll` 替换为了旧版本 `14.00.24215.1`（Visual Studio 2015 时代的版本），覆盖了此前安装的新版 VC++ 2015-2022 Redistributable。更新完成后 MySQL 即无法启动。

攻击链：`Windows Update KB5094126` → `MSVCP140.dll 被降级到 14.0.24215.1` → `mysqld 启动时内存访问违规（0xC0000005）` → `MySQL 服务无法启动` → `IntelliJ IDEA 连接报 Connection Refused`

---

## 根因分析

1. **MySQL 服务未运行**：通过 `Get-Service MySQL` 确认服务处于 `Stopped` 状态。
2. **手动启动失败**：尝试通过 `net start MySQL` 和 `Start-Service` 均无法启动。
3. **直接运行 mysqld.exe 崩溃**：执行 `mysqld --console` 后进程立即退出，退出码 `-1073741819`（即 `0xC0000005`，内存访问违规）。
4. **定位崩溃模块**：通过 Windows 事件查看器（Event ID 1000）确认崩溃发生在 `MSVCP140.dll` 中：

   ```
   出错应用程序名称：mysqld.exe，版本：9.6.0.0
   出错模块名称：MSVCP140.dll，版本：14.0.24215.1
   异常代码：0xc0000005
   ```

5. **确认更新记录**：`Get-HotFix` 显示 KB5094126 于 2026/6/13 由 `NT AUTHORITY\SYSTEM` 安装，为该时间段内唯一的系统变更。
6. **版本不兼容**：MySQL 9.6.0 Commercial 需要较新版本的 VC++ 运行时库，被 KB5094126 降级的 `MSVCP140.dll`（`14.00.24215.1`）无法满足其依赖，导致 mysqld 在初始化阶段直接崩溃，无法产生任何日志输出。这是典型的 **Windows Update 安全补丁覆盖新版 VC++ Runtime 的回归问题**。

---

## 解决方案

1. 从微软官方下载最新的 **Visual C++ 2015-2022 Redistributable (x64)**：
   - 下载地址：`https://aka.ms/vc14/vc_redist.x64.exe`
   - 安装后版本：`14.51.36247.0`（2026 年 5 月发布）

2. 以管理员权限静默安装：
   ```
   vc_redist.x64.exe /install /quiet /norestart
   ```

3. 重新启动 MySQL，端口 3306 恢复正常监听。

---

## 关键收获

- **`0xC0000005` 崩溃 + 无日志** 通常指向运行时库损坏或版本不兼容，而非数据目录或配置问题。
- MySQL 高版本（9.x）对 VC++ Redistributable 版本有严格要求，仅靠 VC++ 2013 或 2015 旧版运行库不足以支撑。
- 排查服务无法启动时，**直接在前台运行 `mysqld --console`** 能比查看服务管理器获得更多线索；若前台也无输出，应立刻检查 Windows 事件查看器中的 `Application Error` 日志。
- 生产环境部署 MySQL 9.x 时，需提前确认目标机器已安装最新的 VC++ 2015-2022 Redistributable。
- **Windows Update 安全补丁可能将 VC++ Runtime DLL 降级到旧版本**，覆盖用户手动安装的新版 Redistributable。当"昨天还好好的今天就坏了"且时间点吻合系统更新时，优先用 `Get-HotFix` 检查近期安装的补丁，再交叉验证相关 DLL 版本是否被回退。修复方法是重新安装最新 Redistributable 覆盖回去。
