# 公告板前后端开发文档

> 功能定位：公告板用于站长在首次给别人使用网站时发布「使用说明、注意事项」等公告。
> 公告板只在**首页**存在：进入首页自动弹出最新一条**启用**状态的公告；首页右上角"写文章"左侧提供**铃铛**入口，用户点击可主动查看；支持**今日关闭**（当天不再自动弹出）；管理员新增/编辑公告后，用户再次进入首页会**重新弹出**（版本对比机制）。

---

## 一、功能概述

### 1.1 用户侧（前台）
| 场景 | 行为 |
| --- | --- |
| 进入首页 | 自动弹出最新一条启用公告 |
| 弹窗按钮"今日关闭" | 当天（本地日期 YYYY-MM-DD）不再自动弹出；点击铃铛仍可查看 |
| 弹窗按钮"关闭" | 只关闭本次弹窗，当天再进首页仍会弹出 |
| 点击首页右上角铃铛 | 主动打开公告弹窗，不受"今日关闭"限制 |
| 铃铛红点 | 有未读公告（当天未关闭，或公告被更新）时显示红点 |
| 公告内容 | 展示标题 + 正文（保留换行）+ 创建时间 |

### 1.2 管理侧（后台）
- 公告的**新增 / 编辑 / 删除 / 启用 / 停用 / 搜索 / 分页**。
- 只有 `status = 1`（启用）的公告才会被前台接口返回。
- 前台展示 **最新一条**（按 `create_time` 倒序取第一条）启用公告，不滚动展示历史公告。
- 管理员**新增**或**编辑**（含启用/停用切换）任意公告后，会刷新该公告的 `update_time`；用户端依据 `update_time` 版本对比，感知到"有新公告"从而重新弹出。

### 1.3 关键规则
- 弹出判断条件：`今天未点"今日关闭"` **或** `本地已读版本 ≠ 最新公告的 update_time`，满足其一即自动弹出。
- 停用公告前台不可见：若最新公告被停用，前台取启用的最新一条；若无启用公告，则首页不弹窗、无红点。

## 二、数据表设计

### 2.1 表结构 `notice`

```sql
DROP TABLE IF EXISTS `notice`;
CREATE TABLE `notice` (
  `id`          BIGINT       NOT NULL AUTO_INCREMENT COMMENT '公告ID',
  `title`       VARCHAR(100) NOT NULL COMMENT '公告标题',
  `content`     TEXT         NOT NULL COMMENT '公告内容（支持换行，按原文展示）',
  `status`      TINYINT      NOT NULL DEFAULT 1 COMMENT '状态：1启用 0停用',
  `create_time` DATETIME     NOT NULL DEFAULT CURRENT_TIMESTAMP COMMENT '创建时间',
  `update_time` DATETIME     NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP COMMENT '更新时间（作为版本号，编辑时强制刷新）',
  PRIMARY KEY (`id`),
  KEY `idx_status` (`status`),
  KEY `idx_create_time` (`create_time`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='公告板';
```

> ⚠️ 注意：`update_time` 是「版本号」核心字段，前端用它判断公告是否有更新，**必须**保证在新增/编辑时被刷新。
> 依赖数据库 `ON UPDATE CURRENT_TIMESTAMP` 即可在 UPDATE 时自动刷新，但**仅在确实修改了行数据时**才会触发；若编辑时字段值没有变化（例如仅重新提交相同内容），`ON UPDATE` 不会更新时间。因此**后端在 UPDATE 时必须显式 `update_time = NOW()`**，确保每次编辑都产生新版本。

`src/main/resources/mapper/NoticeMapper.xml`：

```xml
<?xml version="1.0" encoding="UTF-8"?>
<!DOCTYPE mapper PUBLIC "-//mybatis.org//DTD Mapper 3.0//EN"
        "http://mybatis.org/dtd/mybatis-3-mapper.dtd">
<mapper namespace="com.campus.mapper.NoticeMapper">

    <sql id="base_cols">
        id, title, content, status, create_time, update_time
    </sql>

    <!-- 前台：所有启用公告，最新在前 -->
    <select id="selectActiveList" resultType="com.campus.entity.Notice">
        SELECT <include refid="base_cols"/>
        FROM notice
        WHERE status = 1
        ORDER BY create_time DESC
    </select>

    <!-- 后台：分页列表（含停用），条件可选 -->
    <select id="selectPageList" resultType="com.campus.entity.Notice">
        SELECT <include refid="base_cols"/>
        FROM notice
        <where>
            <if test="keyword != null and keyword != ''">
                AND title LIKE CONCAT('%', #{keyword}, '%')
            </if>
            <if test="status != null">
                AND status = #{status}
            </if>
        </where>
        ORDER BY create_time DESC
        LIMIT #{offset}, #{size}
    </select>

    <select id="selectPageCount" resultType="long">
        SELECT COUNT(*)
        FROM notice
        <where>
            <if test="keyword != null and keyword != ''">
                AND title LIKE CONCAT('%', #{keyword}, '%')
            </if>
            <if test="status != null">
                AND status = #{status}
            </if>
        </where>
    </select>

    <select id="selectById" resultType="com.campus.entity.Notice">
        SELECT <include refid="base_cols"/> FROM notice WHERE id = #{id}
    </select>

    <insert id="insert" useGeneratedKeys="true" keyProperty="id">
        INSERT INTO notice (title, content, status, create_time, update_time)
        VALUES (#{title}, #{content}, #{status}, #{createTime}, #{updateTime})
    </insert>

    <update id="update">
        UPDATE notice
        SET title = #{title},
            content = #{content},
            status = #{status},
            update_time = #{updateTime}
        WHERE id = #{id}
    </update>

    <delete id="deleteById">
        DELETE FROM notice WHERE id = #{id}
    </delete>
</mapper>
```

> ⚠️ 分页返回统一结构：`{ "records": [...], "total": n, "page": 1, "size": 10 }`，与现有后端各分页接口一致。

### 3.5 Service `NoticeService.java`

```java
public interface NoticeService {
    // 前台：所有启用公告，按创建时间倒序（最新在前）
    List<NoticeVO> listActive();

    // 后台：分页 + 条件查询
    PageResult<NoticeVO> adminPage(long page, long size, String keyword, Integer status);

    NoticeVO getById(Long id);

    Long add(NoticeDTO dto);

    void update(Long id, NoticeDTO dto);

    void delete(Long id);
}
```

> `PageResult<T>`：现有后端的通用分页返回封装（`records / total / page / size` 四个字段）。

### 3.6 Service 实现要点 `NoticeServiceImpl.java`

```java
@Service
@RequiredArgsConstructor
public class NoticeServiceImpl implements NoticeService {
    private final NoticeMapper noticeMapper;

    @Override
    public List<NoticeVO> listActive() {
        return noticeMapper.selectActiveList().stream().map(this::toVO).toList();
    }

    @Override
    public PageResult<NoticeVO> adminPage(long page, long size, String keyword, Integer status) {
        long total = noticeMapper.selectPageCount(keyword, status);
        List<NoticeVO> records = noticeMapper.selectPageList((page - 1) * size, size, keyword, status)
                .stream().map(this::toVO).toList();
        return PageResult.of(records, total, page, size);
    }

    @Override
    public NoticeVO getById(Long id) {
        return toVO(noticeMapper.selectById(id));
    }

    @Override
    public Long add(NoticeDTO dto) {
        Notice n = new Notice();
        n.setTitle(dto.getTitle());
        n.setContent(dto.getContent());
        n.setStatus(dto.getStatus() == null ? 1 : dto.getStatus());
        LocalDateTime now = LocalDateTime.now();
        n.setCreateTime(now);
        n.setUpdateTime(now);   // 显式赋值，保证版本号存在
        noticeMapper.insert(n);
        return n.getId();
    }

    @Override
    public void update(Long id, NoticeDTO dto) {
        Notice n = noticeMapper.selectById(id);
        if (n == null) {
            throw new BusinessException("公告不存在");
        }
        // title / content 每次编辑都整体覆盖（停用/启用只传 status 时保留原值）
        if (dto.getTitle() != null) n.setTitle(dto.getTitle());
        if (dto.getContent() != null) n.setContent(dto.getContent());
        if (dto.getStatus() != null) n.setStatus(dto.getStatus());
        // 关键：无论字段是否变化，编辑都强制刷新 update_time，产生新版本，
        // 让用户端"已读版本 != 最新版本"重新弹出公告
        n.setUpdateTime(LocalDateTime.now());
        noticeMapper.update(n);
    }

    @Override
    public void delete(Long id) {
        noticeMapper.deleteById(id);
    }

    private NoticeVO toVO(Notice n) {
        if (n == null) return null;
        NoticeVO v = new NoticeVO();
        v.setId(n.getId());
        v.setTitle(n.getTitle());
        v.setContent(n.getContent());
        v.setStatus(n.getStatus());
        v.setCreateTime(n.getCreateTime());
        v.setUpdateTime(n.getUpdateTime());
        return v;
    }
}
```

> ⚠️ `update()` 整体覆盖 `title / content / status`：管理员从编辑弹窗提交时这三个字段总是有值的；
> 单独的"启用/停用"按钮也只提交 `status`（其余为 null 时保留原值）。无论走哪种路径，**`update_time` 都会被显式刷新**。

### 3.7 Controller `NoticeController.java`

```java
@RestController
@RequestMapping("/notice")
@RequiredArgsConstructor
public class NoticeController {
    private final NoticeService noticeService;

    /** 前台公开接口：启用的公告列表（最新在前），无需登录 */
    @GetMapping("/list")
    public Result<List<NoticeVO>> listActive() {
        return Result.success(noticeService.listActive());
    }

    /** 后台：分页列表，需管理员 */
    @GetMapping("/admin/list")
    public Result<PageResult<NoticeVO>> adminPage(
            @RequestParam(defaultValue = "1") long page,
            @RequestParam(defaultValue = "10") long size,
            @RequestParam(required = false) String keyword,
            @RequestParam(required = false) Integer status) {
        return Result.success(noticeService.adminPage(page, size, keyword, status));
    }

    /** 后台：详情，需管理员 */
    @GetMapping("/{id}")
    public Result<NoticeVO> get(@PathVariable Long id) {
        return Result.success(noticeService.getById(id));
    }

    /** 后台：新增，需管理员 */
    @PostMapping
    public Result<Long> add(@RequestBody @Valid NoticeDTO dto) {
        return Result.success(noticeService.add(dto));
    }

    /** 后台：编辑（含启用/停用），需管理员，会刷新 update_time 版本号 */
    @PutMapping("/{id}")
    public Result<Void> update(@PathVariable Long id, @RequestBody @Valid NoticeDTO dto) {
        noticeService.update(id, dto);
        return Result.success();
    }

    /** 后台：删除，需管理员 */
    @DeleteMapping("/{id}")
    public Result<Void> delete(@PathVariable Long id) {
        noticeService.delete(id);
        return Result.success();
    }
}
```

### 5.2 新增 `src/composables/useNotice.js`（单例共享状态）
模块顶层 `ref` 保证弹窗/铃铛跨组件共享一份状态：

| 状态 | 说明 |
| --- | --- |
| `visible` | 弹窗是否显示 |
| `loading` | 公告加载中 |
| `notice` | 当前最新启用公告 |
| `hasNew` | 是否有未读（铃铛红点） |

localStorage 两个键：

| 键 | 含义 |
| --- | --- |
| `notice_closed_date` | "今日关闭"的日期（YYYY-MM-DD） |
| `notice_seen_version` | 已读公告版本号（最新 `updateTime`） |

**今日关闭 + 版本对比机制**（核心逻辑）：

```
进入首页 autoCheck():
  1. 取最新启用公告 notice（未加载过则请求 /notice/list）
  2. version = notice.updateTime
  3. closedToday = (notice_closed_date == 今天)
  4. seen = (notice_seen_version == version)
  5. 若 closedToday 且 seen → 不弹、无红点（当天已关闭且内容没更新）
  6. 否则 → 弹窗 + 红点
```

- 点击 **"今日关闭"**：写入 `notice_closed_date = 今天` 且 `notice_seen_version = version`。
- 点击 **"关闭"**：只关弹窗，不写任何 localStorage，当天重进首页仍会弹。
- 管理员**新增/编辑公告**后，最新公告的 `updateTime` 变化 → 用户端 `seen != version` → 即使当天点过"今日关闭"也会**重新弹出**。
- 点击**铃铛**：直接打开弹窗（忽略今日关闭），并清除红点。

## 六、注意事项

1. **`update_time` 必须显式刷新**：数据库 `ON UPDATE CURRENT_TIMESTAMP` 只在行数据实际变化时触发，相同内容重新提交不会更新时间。后端 UPDATE 时必须 `setUpdateTime(now)`。
2. **公告只展示最新一条**：前台接口按 `create_time` 倒序返回所有启用公告，前端只取第一条。历史公告不提供滚动展示（如后续需要，可在 `/notice/list` 加 `limit` 参数）。
3. **停用公告不展示**：`status=0` 的公告不会出现在前台；若最新公告被停用，展示更早的启用公告。
4. **匿名可读**：`/notice/list` 必须放行，未登录用户也要能看公告。
5. **版本对比基于 `updateTime` 字符串**：前端直接比较字符串相等性；后端需保证时间格式稳定（建议统一 `yyyy-MM-dd HH:mm:ss`）。
6. **"今日关闭"是本地行为**：每个浏览器各自记录，不清除；用户清浏览器缓存后当天会再次弹出（可接受，属预期）。
7. **弹窗只在首页自动出现**：切换离开首页时关闭弹窗，避免非首页场景悬挂弹窗。
8. **编辑公告触发重新弹出的副作用**：管理员编辑历史公告后，用户会再次看到**最新公告**（无论编辑的是不是它），因为版本号取自"最新公告"。这是当前设计（简单、可预期），如想精确到"编辑哪条弹哪条"需要额外记录已读公告 id，当前不需要。
