## 问题一：PDFBox 3.x API 变更

### 现象

编译报错：
```
java: 找不到符号
  符号:   方法 load(java.io.InputStream)
  位置: 类 org.apache.pdfbox.pdmodel.PDDocument
```

### 根因

PDFBox 3.x 相比 2.x 做了破坏性 API 变更：

| 操作 | PDFBox 2.x | **PDFBox 3.x** |
|------|-----------|---------------|
| 加载 PDF | `PDDocument.load(InputStream)` | ❌ 已移除 |
| 新方式 | — | `Loader.loadPDF(new RandomAccessReadBuffer(inputStream))` |
| 字体加载 | `PDType0Font.Load(document, stream)` | 不变，但需要包一层 |

`InputStream` 在 PDFBox 3.x 中不直接支持，必须包装为 `RandomAccessReadBuffer`。

### 修复

```java
// 之前（PDFBox 2.x）
PDDocument document = PDDocument.load(inputStream);

// 之后（PDFBox 3.x）
PDDocument document = Loader.loadPDF(new RandomAccessReadBuffer(inputStream));
```

### 教训

- 使用一个不熟悉的库时，先查最新版的 API 文档，不要凭旧经验写
- PDFBox 3.x 的官方 migration guide 明确列出了此项变更，开发时应先查阅

## 问题二：`user_id` 不允许为空

### 现象

```
Column 'user_id' cannot be null
```

### 根因

建表 SQL 中 `user_id` 定义为 `BIGINT NOT NULL`，但转换接口允许未登录用户调用（无 `@RequireLogin`），此时 `UserContext.getUserId()` 返回 `null`。

### 修复

```sql
ALTER TABLE convert_record MODIFY user_id BIGINT DEFAULT NULL;
```

### 教训

- 如果接口允许未登录访问，对应的外键/用户 ID 字段必须可空
- 需求分析时要明确：哪些操作必须登录？哪些可以匿名？

## 问题三：`Must call setFont() before showText()`

### 现象

后端抛异常：
```
Must call setFont() before showText()
```

### 根因

PDFBox 要求调用 `showText()` 之前必须调用 `setFont()` 设置字体。原有的 `docxToPdf()` 和 `markdownToPdf()` 方法中，加载中文字体失败后 `font = null`，跳过了 `setFont()`，但后续仍调用了 `showText()`。

### 修复

1. 提取统一字体加载方法 `loadCjkFont()`，按优先级尝试：classpath → Windows TTF → Windows TTC → Linux 字体
2. 所有字体都找不到时直接抛异常，不再静默跳过 `setFont()`

```java
private PDType0Font loadCjkFont(PDDocument pdfDoc) throws IOException {
    // 1. classpath:/fonts/SimSun.ttf
    // 2. C:/Windows/Fonts/msyh.ttf / simsun.ttf
    // 3. C:/Windows/Fonts/msyh.ttc → "Microsoft YaHei"
    // 4. Linux 字体
    // 5. 全失败 → 抛异常，不给 showText 留机会
}
```

### 教训

- PDFBox 生成 PDF 时，`beginText()` → **`setFont()`** → `showText()` → `endText()` 是固定顺序，缺一不可
- 外部资源（字体文件）加载失败要有明确的错误提示，不能静默降级

## 问题四：`resultUrl` 不是完整 URL

### 现象

前端点击「打开结果」按钮后弹出 Whitelabel Error Page（Spring Boot 404）。

### 根因

前端 `resolveResultUrl()` 的 fallback 逻辑：

```
resultUrl = "toolbox/uuid.pdf"     ← 后端返回的是 OSS 对象 key
  → 不是 https?:// 开头
  → 不是 /api 开头
  → 无 VITE_OSS_PUBLIC_BASE
  → 拼接为 http://localhost:8080/toolbox/uuid.pdf
  → Spring Boot 404
```

### 修复方案对比

| 方案 | 说明 | 最终选择 |
|------|------|---------|
| 后端返回完整 OSS URL | 要求 OSS bucket 公开读 | ❌ bucket 私有 |
| 前端配 VITE_OSS_PUBLIC_BASE | 前端拼 URL | ❌ 多一个配置项 |
| **后端增加下载代理接口** | **Controller 从 OSS 拉文件流式输出** | **✅ 最终方案** |

### 最终方案

在 `ToolboxController` 中新增下载端点：

```java
@GetMapping("/api/toolbox/download/{id}")
public void downloadResult(@PathVariable Long id, HttpServletResponse response) {
    // 查 DB → 从 OSS 流式输出
}
```

Service 返回的 `resultUrl` 改为 `/api/toolbox/download/{recordId}`，前端 `window.open()` 走 Vite 代理直达后端。

### 教训

- 后端返回的 URL 必须前端能直接访问
- OSS 私有 bucket 必须后端代理下载，不能直接暴露 key
- 前端 `resolveResultUrl()` 的 fallback 逻辑要谨慎，不要自动拼后端地址

## 问题五：PDF → 图片只渲染了第一页

### 现象

多页 PDF 转 PNG/JPG，结果只有第一页，其余页丢失。

### 根因

```java
// 只渲染了第 0 页（第一页）
BufferedImage image = renderer.renderImageWithDPI(0, 150);
```

没有遍历所有页面。

### 修复

```java
int totalPages = document.getNumberOfPages();
if (totalPages <= 1) {
    // 单页 → 直接返回图片
} else {
    // 多页 → 全部渲染，打成 ZIP 包返回
    try (ZipOutputStream zos = new ZipOutputStream(baos)) {
        for (int i = 0; i < totalPages; i++) {
            BufferedImage image = renderer.renderImageWithDPI(i, 150);
            // ... 写入 ZIP
        }
    }
}
```

同时，下载控制器也做了兼容，ZIP 文件的下载扩展名为 `.zip`。

### 教训

- 处理批量/多页资源时，默认应该遍历所有元素，除非业务明确要求只取第一项
- 多文件输出场景要考虑打包方案（ZIP）

## 问题六：PDF → DOCX 图片和表格丢失

### 现象

PDF 转为 DOCX 后，图片完全消失，表格变成无结构的纯文本。

### 根因

PDFBox 的 `PDFTextStripper` 只负责**按阅读顺序提取文字**，不处理图片和表格：

```
PDF（图片 + 表格 + 文字）
  → PDFTextStripper 只看文字
  → 输出纯文本："姓名\n年龄\n张三\n18"
  → POI 写到 DOCX：只有几行字
```

PDF 是固定布局（坐标定位），DOCX 是流式布局（自动换行），两者本质不同，免费方案中几乎没有能完美互转的库。

### 解决方案对比

| 方案 | 图片 | 表格 | 排版 | 成本 |
|------|------|------|------|------|
| PDFBox + POI（降级） | ❌ | ❌ | ❌ | 无 |
| **LibreOffice 方案** | **✅** | **✅ 大部分** | **✅ 较好** | 安装包 ~300MB |
| Aspose 商业库 | ✅ 完美 | ✅ 完美 | ✅ 完美 | 付费授权 |
| PDF → PNG 截图 | ✅ 100% | ✅ 100% | ✅ 100% | 不可编辑 |

### 最终方案：LibreOffice

在本机（Windows）上安装 LibreOffice，后端优先调用 `soffice --headless` 命令行转换，LibreOffice 不可用时降级回 PDFBox。

#### 新增文件

`convert/LibreOfficeConverter.java` — 工具类，封装命令行调用

```java
ProcessBuilder pb = new ProcessBuilder(
    "C:/Program Files/LibreOffice/program/soffice.exe",
    "--headless", "--convert-to", targetFormat,
    "--outdir", tempDir, inputPath
);
```

#### 自动降级策略

```java
// 伪代码
if (libreOfficeConverter != null) {
    return libreOfficeConverter.pdfToDocx(inputStream);  // 保真
}
// 降级
return pdfboxFallback(inputStream);  // 纯文本
```

#### 配置项

```yaml
toolbox:
  convert:
    libreoffice:
      soffice-path: C:/Program Files/LibreOffice/program/soffice.exe
      timeout-seconds: 30
```

## 架构决策总结

### 最终接口设计

| 接口 | 方法 | 认证 | 说明 |
|------|------|------|------|
| `/api/toolbox/convert` | POST | 可选 | 文件转换，未登录可用 |
| `/api/toolbox/convert/supported-types` | GET | 否 | 获取支持格式 |
| `/api/toolbox/convert/history` | GET | 需登录 | 转换记录列表 |
| `/api/toolbox/download/{id}` | GET | 否 | 下载转换结果（OSS 代理） |
| `/api/toolbox/convert/{id}` | DELETE | 需登录 | 删除记录 |

### 技术栈

| 组件 | 用途 |
|------|------|
| PDFBox 3.0.7 | PDF 读取、文本提取、PDF 渲染为图片 |
| Apache POI 5.3.0 | DOCX 读写 |
| Thumbnailator 0.4.20 | 图片格式转换、缩放 |
| flexmark 0.64.8 | Markdown ↔ HTML 转换 |
| LibreOffice | 高质量文档格式互转（PDF↔DOCX、DOCX↔PDF） |
| 阿里云 OSS | 文件存储（源文件 + 转换结果） |

### 关键原则

1. **纯前端工具不走后端**：JSON 格式化、Base64、时间戳等浏览器端完成
2. **后端只做浏览器做不了的**：PDF/Word 解析、图片格式转换、文档格式互转
3. **下载全走后端代理**：不暴露 OSS 私密 bucket，防止未授权访问
4. **优先保真，自动降级**：LibreOffice → PDFBox/POI 逐级降级
5. **匿名可用**：核心转换功能不强制登录，降低使用门槛
