# 小工具箱模块开发总结

## 项目概述

小怀风的小破站 — 小工具箱模块，提供文件格式转换功能。前端 Vue 3 + Element Plus，后端 Spring Boot 3.5 + MyBatis + MySQL。所有文件存储在阿里云 OSS，下载通过后端代理。

## 问题汇总

### 1. PDFBox 3.x API 变更

| 项目 | 内容 |
|------|------|
| 错误 | `PDDocument.load()` 找不到符号 |
| 原因 | PDFBox 3.x 移除了 `PDDocument.load()`，改为 `Loader.loadPDF()` |
| 还多了 | `InputStream` 不能直接用，要包一层 `RandomAccessReadBuffer` |
| 修复 | `Loader.loadPDF(new RandomAccessReadBuffer(inputStream))` |

### 2. 数据库列约束

| 项目 | 内容 |
|------|------|
| 错误 | `Column 'user_id' cannot be null` |
| 原因 | 转换接口允许未登录用，`UserContext.getUserId()` 返回 `null`，但表字段是 `NOT NULL` |
| 修复 | `ALTER TABLE convert_record MODIFY user_id BIGINT DEFAULT NULL` |

### 3. PDFBox 字体缺失

| 项目 | 内容 |
|------|------|
| 错误 | `Must call setFont() before showText()` |
| 原因 | `loadCjkFont()` 返回 `null` 时跳过了 `setFont()`，但后面还调了 `showText()` |
| 修复 | 统一字体加载方法，全路径找不到时直接抛异常（不留给 `showText()` 机会） |

### 4. 下载地址不是完整 URL

| 项目 | 内容 |
|------|------|
| 错误 | Whitelabel Error Page 404 |
| 原因 | 后端返回 OSS key（如 `toolbox/uuid.pdf`），前端拼到后端地址上 → 404 |
| 方案对比 | OSS 直链需要 bucket 公开；前端拼 URL 要多配一个环境变量 |
| 修复方案 | **后端增加代理下载接口 `/api/toolbox/download/{id}`**，从 OSS 拉到响应流 |
| 结果 | `resultUrl` 返回 `/api/toolbox/download/{id}`，前端走 Vite 代理直达后端 |

### 5. PDF→图片只渲染第一页

| 项目 | 内容 |
|------|------|
| 错误 | 多页 PDF 转 PNG 只有第一页 |
| 原因 | `renderImageWithDPI(0, 150)` — 只传了 0，没遍历所有页 |
| 修复 | 检测 `document.getNumberOfPages()`，单页直接返回，多页全部渲染后打 ZIP 包 |

### 6. LibreOffice 集成失败

| 项目 | 内容 |
|------|------|
| 错误 | `Could not find platform independent libraries` + `no export filter` |
| 原因 | LibreOffice 26.2 的 PDF 导入过滤器依赖 Java，但本机 Java 环境与 LibreOffice 加载 JVM 的方式不兼容 |
| 排查过程 | ① 确认 `soffice.exe` 本身正常 → ② 确认 JDK 17/25 PATH 设置正确 → ③ 发现 `SAL_USE_JAVA=FALSE` 无效 → ④ 确认 TXT→PDF/DOCX→PDF 不受影响（不依赖 Java） → ⑤ 确认 PDF→DOCX 需要 Java 且无法绕过 |
| 结论 | **LibreOffice 保持，用于 DOCX→PDF 和 MD→PDF；PDF→DOCX 用图片嵌入方案** |

### 7. 三级降级策略

| 级别 | 方案 | 图片 | 表格 | 文字可编辑 | 依赖 |
|------|------|------|------|-----------|------|
| 1 | LibreOffice 命令行 | ✅ | ✅ | ✅ | soffice.exe |
| 2 | PDF 每页渲染为图片嵌入 DOCX | ✅ 100% | ✅ 100% | ❌ | 无 |
| 3 | PDFBox 纯文本提取 | ❌ | ❌ | ✅ | 无 |

当前因 Java 环境问题，自动走第 2 级。

### 8. InputStream 多级消费 + 空白页

| 问题 | 原因 | 修复 |
|------|------|------|
| `End-of-File, expected line` | 降级时各级共用同一个 `InputStream`，前一级消费完后一级读到空流 | 开头一次性 `readAllBytes()`，各级共用 `byte[]` |
| 空白页 | 分页符和图片各占一个独立段落，多翻了一页 | 分页符打在图片段落上 `imgParagraph.setPageBreak(true)` |

## 当前架构

### 接口设计

| 接口 | 方法 | 登录 | 说明 |
|------|------|------|------|
| `/api/toolbox/convert` | POST | 可选 | 文件转换 |
| `/api/toolbox/convert/supported-types` | GET | 否 | 获取支持格式 |
| `/api/toolbox/convert/history` | GET | 是 | 转换记录 |
| `/api/toolbox/download/{id}` | GET | 否 | 从 OSS 代理下载 |
| `/api/toolbox/convert/{id}` | DELETE | 是 | 删除记录 |

## 经验教训

1. **新库先查 API 文档**：PDFBox 3.x 比 2.x 改了多处 API，先看 migration guide 可以少踩坑
2. **异常要明确抛出**：字体加载失败直接报错，比静默跳过后在 `showText` 崩溃更容易排查
3. **降级策略要把流缓存好**：多级降级时提前 `readAllBytes()`，避免流被消费后 EOF
4. **下载用代理更稳**：直接暴露 OSS key 需要 bucket 公开，后端代理下载安全性高、前端零配置
5. **LibreOffice 集成要考虑 Java 环境**：LibreOffice 的 PDF 过滤器依赖 JVM，不是所有环境都能跑通
6. **分页要放在同一个段落上**：分页符和内容各占一个段落会多出一页空白
