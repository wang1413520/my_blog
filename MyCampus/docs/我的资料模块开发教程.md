# 我的资料模块开发教程

## 一、概述

本文档记录了个人博客后端项目中"我的资料（User Profile Detail）"模块的完整开发过程，包括数据库设计、后端代码实现、接口联调说明。

### 1.1 技术栈

| 层级 | 技术 |
|------|------|
| 框架 | Spring Boot 3.5.14 |
| ORM | MyBatis 3 + XML Mapper |
| 数据库 | MySQL 8.0 |
| 认证 | JWT + LoginInterceptor |
| 简化代码 | Lombok |

### 1.2 模块定位

"我的资料"是用户中心的扩展模块，用于存储用户更完整的个人档案（真实姓名、性别、生日、联系方式、学校信息、个人简介等）。

**为什么独立建表而非扩展 `user` 表？**

1. 与账号基础信息（用户名、密码、头像）职责分离
2. 避免对现有登录、注册逻辑产生影响
3. 便于后续继续扩展（如增加社交链接、技能标签等）
4. 降低改动风险

## 二、数据库设计

### 2.1 建表 SQL

文件位置：`docs/user_profile_detail.sql`

```sql
CREATE TABLE IF NOT EXISTS user_profile_detail (
    id           BIGINT PRIMARY KEY AUTO_INCREMENT COMMENT '主键ID',
    user_id      BIGINT NOT NULL UNIQUE COMMENT '用户ID，与user表一对一',
    real_name    VARCHAR(30) DEFAULT NULL COMMENT '真实姓名',
    gender       VARCHAR(10) DEFAULT NULL COMMENT '性别：male/female/unknown',
    birthday     DATE DEFAULT NULL COMMENT '出生日期',
    phone        VARCHAR(20) DEFAULT NULL COMMENT '手机号',
    email        VARCHAR(100) DEFAULT NULL COMMENT '邮箱',
    school       VARCHAR(100) DEFAULT NULL COMMENT '学校',
    college      VARCHAR(100) DEFAULT NULL COMMENT '学院',
    major        VARCHAR(100) DEFAULT NULL COMMENT '专业',
    grade        VARCHAR(30) DEFAULT NULL COMMENT '年级',
    location     VARCHAR(100) DEFAULT NULL COMMENT '所在城市',
    bio          VARCHAR(300) DEFAULT NULL COMMENT '个人简介',
    created_at   DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP COMMENT '创建时间',
    updated_at   DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP COMMENT '更新时间',
    CONSTRAINT uk_user_profile_detail_user UNIQUE (user_id),
    INDEX idx_user_profile_detail_user_id (user_id)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='用户资料扩展表';
```

### 2.2 执行方式

```bash
mysql -u root -p your_database < docs/user_profile_detail.sql
```

### 2.3 表关系

```
user (1) ────── (1) user_profile_detail
   ↑                      ↑
 用户基础表            资料扩展表
 (user_id = user_id)
```

- `user_id` 上加了 `UNIQUE` 约束，保证一个用户只有一条资料记录
- 查询时用 `user_id` 即可精确定位

## 四、各层代码详解

### 4.1 实体类 UserProfileDetail.java

```java
@Data
public class UserProfileDetail {
    private Long id;
    private Long userId;
    private String realName;
    private String gender;         // male / female / unknown
    private LocalDate birthday;    // 数据库 DATE → Java LocalDate
    private String phone;
    private String email;
    private String school;
    private String college;
    private String major;
    private String grade;
    private String location;
    private String bio;
    private LocalDateTime createdAt;
    private LocalDateTime updatedAt;
}
```

**注意：** `birthday` 在实体中是 `LocalDate`，但在 DTO 和 VO 中都是 `String`。

### 4.2 DTO 层

**UserProfileDetailUpdateDTO** — 唯一的请求体 DTO：

```java
@Data
public class UserProfileDetailUpdateDTO {
    private String realName;
    private String gender;
    private String birthday;   // "yyyy-MM-dd"，字符串接收，Service 层转 LocalDate
    private String phone;
    private String email;
    private String school;
    private String college;
    private String major;
    private String grade;
    private String location;
    private String bio;
}
```

**为什么 `birthday` 用 `String` 而非 `LocalDate`？**

- 与前端格式 `yyyy-MM-dd` 完全一致
- 避免 Jackson 反序列化时的日期格式问题
- Service 层再做转换，校验更可控

### 4.3 VO 层 UserProfileDetailVO.java

```java
@Data
public class UserProfileDetailVO {
    private Long userId;
    private String realName;
    private String gender;
    private String birthday;     // "yyyy-MM-dd"
    private String phone;
    private String email;
    private String school;
    private String college;
    private String major;
    private String grade;
    private String location;
    private String bio;
    private String createTime;   // "yyyy-MM-dd HH:mm:ss"
    private String updateTime;   // "yyyy-MM-dd HH:mm:ss"
}
```

**与 MemoVO 的时间格式不同：**

| 模块 | 时间格式 |
|------|----------|
| 备忘录 `MemoVO` | 13位毫秒时间戳（`Long`） |
| 我的资料 `UserProfileDetailVO` | `yyyy-MM-dd HH:mm:ss` 字符串 |

原因：前端"我的资料"页面按文档要求使用字符串日期格式。

### 4.4 Mapper 层

**UserProfileDetailMapper.java** — 3 个数据操作方法：

| 方法 | SQL类型 | 说明 |
|------|---------|------|
| `selectByUserId` | SELECT | 按 userId 查资料（可能返回 null） |
| `insert` | INSERT | 首次保存（useGeneratedKeys） |
| `updateByUserId` | UPDATE | 后续保存（WHERE user_id = #{userId}） |

**UserProfileDetailMapper.xml** — 更新 SQL 只动资料字段和 `updated_at`，不动 `created_at`：

```sql
UPDATE user_profile_detail
SET real_name = #{entity.realName},
    ...
    updated_at = NOW()
WHERE user_id = #{entity.userId}
```

### 4.5 Service 层

**UserProfileDetailService.java** — 2 个方法：

| 方法 | 说明 |
|------|------|
| `getByUserId(Long)` | 查询资料，无记录时返回空对象 |
| `saveOrUpdate(Long, DTO)` | 首次插入 / 后续更新 |

**UserProfileDetailServiceImpl.java** — 实现要点：

#### 查询逻辑

```
selectByUserId(userId)
    ├── null → 返回空 VO（仅含 userId），code = 200
    └── 有值 → 转 VO 返回
```

关键代码：

```java
if (entity == null) {
    UserProfileDetailVO empty = new UserProfileDetailVO();
    empty.setUserId(userId);
    return empty;   // 不抛异常，不返回 404
}
```

#### 保存逻辑（saveOrUpdate）

```
1. validate(dto)  —— 校验所有字段合法性
2. DTO → Entity   —— 字段映射 + trimToNull + birthday String→LocalDate
3. selectByUserId → 判断是否已有记录
    ├── null → insert
    └── 有值 → updateByUserId
```

#### 字段校验规则

| 字段 | 校验规则 | 失败 message |
|------|----------|-------------|
| `gender` | 仅允许 `male` / `female` / `unknown`（null/空串放行） | `性别参数不合法` |
| `birthday` | 非空时必须合法日期 `yyyy-MM-dd` | `出生日期格式错误` |
| `phone` | 非空时必须匹配 `1[3-9]\d{9}` | `手机号格式不正确` |
| `email` | 非空时必须匹配邮箱格式 | `邮箱格式不正确` |
| `bio` | 最长 300 字符 | `个人简介不能超过300个字符` |

#### 字符串标准化

```java
private String trimToNull(String value) {
    if (value == null) return null;
    String trimmed = value.trim();
    return trimmed.isEmpty() ? null : trimmed;
}
```

所有字符串字段统一 trim 后入库，空串统一存 `NULL`。

### 4.6 Controller 层

新增的两个端点直接放在 **UserController** 中（文档建议集中管理用户接口）：

| 方法 | 路径 | 说明 |
|------|------|------|
| `GET` | `/api/user/profile/detail` | 查询资料详情 |
| `PUT` | `/api/user/profile/detail` | 保存资料 |

#### 查询接口

```java
@RequireLogin
@GetMapping("/api/user/profile/detail")
public Result<UserProfileDetailVO> getProfileDetail() {
    Long userId = UserContext.getUserId();
    UserProfileDetailVO vo = userProfileDetailService.getByUserId(userId);
    return Result.success(vo);
}
```

#### 保存接口

```java
@RequireLogin
@PutMapping("/api/user/profile/detail")
public Result<Boolean> saveProfileDetail(@RequestBody UserProfileDetailUpdateDTO dto) {
    Long userId = UserContext.getUserId();
    userProfileDetailService.saveOrUpdate(userId, dto);
    return Result.success(true);
}
```

**两条接口都与现有 UserController 的接口路径对齐：**

```
/api/user/register      ← 注册
/api/user/login         ← 登录
/api/user/info          ← 基本信息
/api/user/update        ← 修改昵称/头像
/api/user/password      ← 修改密码
/api/user/avatar        ← 上传头像
/api/user/profile/detail  ← 我的资料（新增）
```

## 五、安全设计

### 5.1 userId 来源

```
userId = UserContext.getUserId()
       = LoginInterceptor 从 Token 中解析
       ≠ 前端请求体传入
```

**严禁前端传 `userId`！** 所有归属判断从 JWT Token 获取。

### 5.2 鉴权流程

```
请求 → @RequireLogin → LoginInterceptor
     → 解析 Authorization: Bearer <token>
     → UserContext.setUser(userId, username)
     → Controller 中 UserContext.getUserId()
     → 只能操作自己的数据
```

### 5.3 数据隔离

操作 `user_profile_detail` 表时都以 `user_id` 为条件：

| 操作 | WHERE 条件 |
|------|-----------|
| 查询 | `WHERE user_id = #{userId}` |
| 更新 | `WHERE user_id = #{userId}` |
| 插入 | `VALUES (..., #{userId}, ...)` |

## 七、与现有接口的关系

| 接口 | 职责 | 说明 |
|------|------|------|
| `GET /api/user/info` | 查基础信息 | 用户名、昵称、头像、角色（来自 `user` 表） |
| `PUT /api/user/update` | 改基础信息 | 改昵称/头像（来自 `user` 表） |
| `GET /api/user/profile/detail` | 查资料详情 | 真实姓名、性别、生日等（来自 `user_profile_detail` 表） |
| `PUT /api/user/profile/detail` | 保存资料 | writto `user_profile_detail` 表 |

**职责清晰分离：** 账号信息归 `user` 表，个人档案归 `user_profile_detail` 表。

## 八、联调验收清单

- [ ] 未登录访问资料接口返回 `code = 401`
- [ ] 首次查询无资料时返回 `code = 200` + `{ userId: xx }`
- [ ] 首次保存执行 INSERT，再次保存执行 UPDATE
- [ ] `gender` 传非法值时被拦截
- [ ] `birthday` 传非法日期时被拦截
- [ ] `phone` 格式不正确时被拦截
- [ ] `email` 格式不正确时被拦截
- [ ] `bio` 超过 300 字符时被拦截
- [ ] 用户 A 无法看到/修改用户 B 的资料
- [ ] 返回字段名完全匹配前端文档（`userId`, `realName`, `gender`, `birthday` 等）
- [ ] 日期字段格式为 `yyyy-MM-dd` / `yyyy-MM-dd HH:mm:ss`

## 九、启动步骤

```bash
# 1. 建表
mysql -u root -p your_database < docs/user_profile_detail.sql

# 2. 启动后端
cd MyCampus
mvn spring-boot:run

# 3. 测试接口
# 先登录获取 token
curl -X POST http://localhost:8080/api/user/login \
  -H "Content-Type: application/json" \
  -d '{"username":"test","password":"123456"}'

# 用返回的 token 查询资料
curl http://localhost:8080/api/user/profile/detail \
  -H "Authorization: Bearer <token>"

# 保存资料
curl -X PUT http://localhost:8080/api/user/profile/detail \
  -H "Authorization: Bearer <token>" \
  -H "Content-Type: application/json" \
  -d '{"realName":"张三","gender":"male","bio":"测试简介"}'
```
