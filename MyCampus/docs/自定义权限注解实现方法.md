## 一、理解权限注解

### 1.1 什么是权限注解？

权限注解是 **自定义 Java 注解**，贴在 Controller 方法上，声明该接口的访问约束：

| 注解 | 含义 | 约束 |
|------|------|------|
| `@RequireLogin` | 需要登录 | Token 必须有效 |
| `@RequireAdmin` | 需要管理员 | Token 有效 + 角色为管理员（`role=1`） |

### 1.2 注解元数据

```java
// @RequireLogin.java
@Target(ElementType.METHOD)      // 只能标注在方法上
@Retention(RetentionPolicy.RUNTIME) // 运行时保留，反射可读
public @interface RequireLogin {
}
```

```java
// @RequireAdmin.java
@Target(ElementType.METHOD)
@Retention(RetentionPolicy.RUNTIME)
public @interface RequireAdmin {
}
```

关键点：

- `@Target(ElementType.METHOD)` — 标注在 Controller 方法上，与 `@GetMapping` 等配合使用
- `@Retention(RetentionPolicy.RUNTIME)` — JVM 运行时可通过反射读取，AOP 和拦截器都依赖此机制
- 注解本身没有逻辑，逻辑由 **拦截器** 或 **切面** 实现

## 二、方式一：HandlerInterceptor（拦截器）

> **这是本项目当前使用的方式。** 通过 Spring MVC 的 `HandlerInterceptor`，在请求进入 Controller 之前拦截，检查注解并验证 Token。

### 2.1 整体流程

```
客户端请求
    ↓
Interceptor.preHandle()  ←—— 在这里检查 @RequireLogin / @RequireAdmin
    ↓ 校验通过
Controller 方法执行
    ↓
Interceptor.afterCompletion()  ←—— 清理 ThreadLocal
```

### 2.2 实现步骤

#### Step 1：定义注解（同上）

#### Step 2：实现拦截器

```java
// LoginInterceptor.java
@Slf4j
@Component
public class LoginInterceptor implements HandlerInterceptor {

    @Autowired
    private UserMapper userMapper;

    @Override
    public boolean preHandle(HttpServletRequest request,
                             HttpServletResponse response,
                             Object handler) throws Exception {
        // 1. 非方法请求（如静态资源）直接放行
        if (!(handler instanceof HandlerMethod)) {
            return true;
        }

        HandlerMethod handlerMethod = (HandlerMethod) handler;

        // 2. 读取方法上的注解
        boolean requireAdmin = handlerMethod.hasMethodAnnotation(RequireAdmin.class);
        boolean requireLogin = handlerMethod.hasMethodAnnotation(RequireLogin.class);

        // 3. 不需要权限，直接放行
        if (!requireAdmin && !requireLogin) {
            return true;
        }

        // 4. 从请求头获取 Token
        String token = extractToken(request); // 省略提取逻辑

        // 5. 解析 Token，验证身份
        Claims claims = JWT.parseToken(token);
        Long userId = Long.valueOf(claims.getSubject());

        // 6. 存入 ThreadLocal，当前线程全局可获取
        UserContext.setUser(userId, claims.get("username", String.class));

        // 7. @RequireAdmin 需额外校验角色
        if (requireAdmin) {
            Integer role = userMapper.selectRoleByUserId(userId);
            if (role == null || role != 1) {
                response.setStatus(403);
                response.getWriter().write("{\"code\":403,\"message\":\"仅管理员可访问\"}");
                return false;
            }
        }

        return true;
    }

    @Override
    public void afterCompletion(HttpServletRequest request,
                                HttpServletResponse response,
                                Object handler, Exception ex) {
        // 请求结束，清理 ThreadLocal，防止内存泄漏
        UserContext.clear();
    }
}
```

#### Step 3：注册拦截器

```java
// WenConfig.java
@Configuration
public class WenConfig implements WebMvcConfigurer {

    @Autowired
    private LoginInterceptor loginInterceptor;

    @Override
    public void addInterceptors(InterceptorRegistry registry) {
        registry.addInterceptor(loginInterceptor)
                .addPathPatterns("/api/**")                    // 拦截 /api/ 下所有请求
                .excludePathPatterns(
                        "/api/user/login",                     // 登录接口
                        "/api/user/register"                   // 注册接口
                );
    }
}
```

#### Step 4：在 Controller 上使用

```java
@RestController
public class MemoController {

    @RequireLogin
    @GetMapping("/api/memo/list")
    public Result listMemos() {
        Long userId = UserContext.getUserId();  // 从 ThreadLocal 获取当前用户
        // ...
    }
}

@RestController
public class AdminDashboardController {

    @RequireAdmin
    @GetMapping("/api/admin/overview")
    public Result overview() {
        // 能走到这里的一定是管理员
        // ...
    }
}
```

### 2.3 ThreadLocal 传递用户信息

当前用户信息通过 `UserContext`（基于 ThreadLocal）传递，无需在方法签名中传参：

```java
public class UserContext {
    private static final ThreadLocal<Long> USER_ID_HOLDER = new ThreadLocal<>();
    private static final ThreadLocal<String> USERNAME_HOLDER = new ThreadLocal<>();

    public static void setUser(Long userId, String username) { ... }
    public static Long getUserId() { return USER_ID_HOLDER.get(); }
    public static String getUsername() { return USERNAME_HOLDER.get(); }
    public static void clear() { /* 在 afterCompletion 中调用 */ }
}
```

使用方式：任何地方调用 `UserContext.getUserId()` 即可获取当前登录用户 ID。

### 2.4 关键设计要点

| 要点 | 说明 |
|------|------|
| **实例检查** | `handler instanceof HandlerMethod` 过滤非方法请求（静态资源等） |
| **注解读取** | `handlerMethod.hasMethodAnnotation(RequireAdmin.class)` 比反射更简洁 |
| **Token 提取** | 兼容 `Bearer xxx` 和裸 Token 两种格式 |
| **ThreadLocal 清理** | `afterCompletion()` 必须清理，否则内存泄漏 |
| **@RequireAdmin 隐含登录** | `@RequireAdmin` 不需要同时写 `@RequireLogin`，拦截器自动处理 |

## 三、方式二：AOP（面向切面编程）

> AOP 通过切面在方法执行前后织入权限检查逻辑，优点是粒度更细（可以切入 Service 层），缺点是拿不到 `HttpServletRequest` / `HttpServletResponse`。

### 3.1 Maven 依赖

```xml
<dependency>
    <groupId>org.springframework.boot</groupId>
    <artifactId>spring-boot-starter-aop</artifactId>
</dependency>
```

### 3.2 实现步骤

#### Step 1：定义注解（同上）

#### Step 2：编写切面

```java
@Aspect
@Component
public class PermissionAspect {

    @Autowired
    private UserMapper userMapper;

    /**
     * 环绕通知：在方法执行前后进行权限校验
     */
    @Around("@annotation(com.wang.mycampus.annotation.RequireLogin) || " +
            "@annotation(com.wang.mycampus.annotation.RequireAdmin)")
    public Object checkPermission(ProceedingJoinPoint joinPoint) throws Throwable {
        MethodSignature signature = (MethodSignature) joinPoint.getSignature();
        Method method = signature.getMethod();

        boolean requireAdmin = method.isAnnotationPresent(RequireAdmin.class);

        // 从请求上下文获取 Token
        // 注意：AOP 环境下获取 HttpServletRequest 需要 RequestContextHolder
        HttpServletRequest request = ((ServletRequestAttributes)
                RequestContextHolder.currentRequestAttributes()).getRequest();

        String token = extractToken(request);
        Claims claims = JWT.parseToken(token);
        Long userId = Long.valueOf(claims.getSubject());

        // 存入 ThreadLocal
        UserContext.setUser(userId, claims.get("username", String.class));

        // 管理员校验
        if (requireAdmin) {
            Integer role = userMapper.selectRoleByUserId(userId);
            if (role == null || role != 1) {
                throw new RuntimeException("仅管理员可访问");
            }
        }

        try {
            return joinPoint.proceed();  // 放行，执行原方法
        } finally {
            UserContext.clear();          // 清理
        }
    }
}
```

#### Step 3：在 Controller / Service 上使用

```java
@RequireLogin
@GetMapping("/api/memo/list")
public Result listMemos() {
    Long userId = UserContext.getUserId();
    // ...
}
```

AOP 的优势在于**可以切入 Service 层**：

```java
@Service
public class MemoServiceImpl implements MemoService {

    @RequireLogin  // 也可以在 Service 方法上使用
    public List<MemoVO> listMemos() {
        Long userId = UserContext.getUserId();
        // ...
    }
}
```

### 3.3 异常处理与响应

AOP 切面中无法直接操作 `HttpServletResponse`（不像拦截器有 `response` 参数），因此通常通过 **抛异常 + 全局异常处理器** 的方式返回错误：

```java
// 切面中抛出异常
throw new UnauthorizedException("请先登录");

// 全局异常处理器统一返回 JSON
@RestControllerAdvice
public class GlobalExceptionHandler {
    @ExceptionHandler(UnauthorizedException.class)
    public Result handleUnauthorized(UnauthorizedException e) {
        return Result.error(401, e.getMessage());
    }
}
```

## 四、两种方式对比

| 维度 | HandlerInterceptor | AOP |
|------|-------------------|-----|
| **实现原理** | Spring MVC 组件，在 HandlerAdapter 之前调用 | Spring AOP 动态代理，在方法调用前后织入 |
| **适用范围** | 仅 Controller 层（HandlerMethod） | Controller、Service、任意 Spring Bean |
| **获取 Request/Response** | 直接通过方法参数 | 需 `RequestContextHolder` 间接获取 |
| **返回错误响应** | 直接操作 `response.getWriter()` | 推荐抛异常 + `@ExceptionHandler` |
| **拦截粒度** | 路径级别（`addPathPatterns` + 注解） | 注解级别（`@annotation` 切点） |
| **性能开销** | 极小（每次请求一次 instanceof 检查） | 极小（AOP 代理，无反射调用） |
| **代码侵入性** | 配置拦截路径，注解只贴需要的方法 | 注解只贴需要的方法 |
| **典型场景** | Web 层权限校验、日志、CORS | 事务、缓存、审计日志、Service 层权限 |

### 4.1 如何选择？

- **只用 Controller 层鉴权 → 选 Interceptor**（更简单、更直接）
- **需要在 Service 层也鉴权 → 选 AOP**（例：@RequireAdmin 贴在 Service 方法上）
- **需要操作 Response 状态码/响应体 → 选 Interceptor**
- **需要统一的异常流 → 选 AOP + 全局异常处理器**
- **两者可以共存**：Interceptor 做通用校验（Token 解析），AOP 做细粒度权限

## 五、项目现状与最佳实践

### 5.1 本项目架构图

```
WenConfig (注册拦截器)
    ↓
LoginInterceptor.preHandle()
    ├─ 检查 @RequireLogin / @RequireAdmin
    ├─ 解析 JWT Token (JWT.parseToken)
    ├─ 存入 UserContext (ThreadLocal)
    └─ 校验管理员角色 (UserMapper.selectRoleByUserId)
        ↓
Controller 方法  ←── 通过 @RequireLogin / @RequireAdmin 声明权限
        ↓
LoginInterceptor.afterCompletion()
    └─ UserContext.clear()
```

### 5.2 使用时注意事项

1. **`@RequireAdmin` 无需额外写 `@RequireLogin`**
   - 拦截器中 `requireAdmin` 分支自动处理 Token 解析，不需要 `requireLogin` 配合

2. **Token 提取兼容两种格式**
   - `Authorization: Bearer eyJhbGci...` — 剥去 `Bearer ` 前缀
   - `Authorization: eyJhbGci...` — 直接使用

3. **排除的路径**
   - 注册拦截器时已在 `WenConfig` 中排除 `/api/user/login` 和 `/api/user/register`
   - 如果新增无需登录的接口（如公开 API），需要在此处或添加新的排除

4. **ThreadLocal 务必清理**
   - 当前代码已在 `afterCompletion()` 清理，确保**不遗漏异常路径**
   - 如果使用 AOP，在 `finally` 块中清理

5. **Token 过期处理**
   - 拦截器中捕获 `JwtException`，返回 401 JSON
   - 前端收到 401 后应清空本地 Token 并跳转到登录页

### 5.3 如何新增权限注解？

以新增 `@RequireVIP` 为例：

**① 定义注解**

```java
@Target(ElementType.METHOD)
@Retention(RetentionPolicy.RUNTIME)
public @interface RequireVIP {
}
```

**② 拦截器（或者 AOP）中增加判断**

```java
// LoginInterceptor.preHandle() 中增加
boolean requireVIP = handlerMethod.hasMethodAnnotation(RequireVIP.class);
if (requireVIP) {
    Integer level = userMapper.selectVipLevelByUserId(userId);
    if (level == null || level < 1) {
        response.setStatus(403);
        response.getWriter().write("{\"code\":403,\"message\":\"需要 VIP 会员\"}");
        return false;
    }
}
```

**③ 在 Controller 方法上使用**

```java
@RequireVIP
@GetMapping("/api/vip/content")
public Result getVipContent() {
    // ...
}
```

## 六、扩展：更多自定义注解

### 6.1 带参数的权限注解

如果权限判断需要参数，可以在注解中定义属性：

```java
@Target(ElementType.METHOD)
@Retention(RetentionPolicy.RUNTIME)
public @interface RequireRole {
    String[] value() default {};       // 多个角色
    String logic() default "OR";       // AND / OR
}
```

**使用示例：**

```java
@RequireRole({"admin", "moderator"})
@GetMapping("/api/moderate")
public Result moderate() { ... }
```

**拦截器中读取：**

```java
RequireRole roleAnno = handlerMethod.getMethodAnnotation(RequireRole.class);
String[] roles = roleAnno.value();
String logic = roleAnno.logic();
// 校验逻辑...
```

### 6.2 限流注解（Rate Limiting）

```java
@Target(ElementType.METHOD)
@Retention(RetentionPolicy.RUNTIME)
public @interface RateLimit {
    int value() default 10;  // 每秒允许请求数
}
```

可实现 AOP 切面配合 Redis / Guava RateLimiter 做接口限流。
