# 文件转换工具依赖库教学报告

## 前言

本文档详细讲解小工具箱后端用到的三个核心库：**PDFBox**、**Apache POI**、**Thumbnailator**，以及辅助库 **flexmark** 的使用方法。每个库都会从「是什么」「为什么用它」「怎么用」「踩坑点」四个角度展开。

---

## 一、Apache PDFBox 3.x — PDF 处理

### 1.1 是什么

PDFBox 是一个纯 Java 的 PDF 处理库，无需安装任何外部软件。它可以：

- 读取 PDF 提取文本（`PDFTextStripper`）
- 将 PDF 每一页渲染为图片（`PDFRenderer`）
- 创建新的 PDF 并写入文本/图形（`PDPageContentStream`）
- 合并/拆分 PDF 文件

v3.x 相比 2.x 改用了 Java 17+ 的模块化 API。

### 1.2 核心类

| 类名 | 作用 | 类比 |
|------|------|------|
| `PDDocument` | 代表一个 PDF 文档，一切操作的入口 | 像 `File` 对象 |
| `PDPage` | 代表 PDF 中的一页 | 像一张画纸 |
| `PDPageContentStream` | 向页面写入内容的画笔 | 像 `Graphics2D` |
| `PDFTextStripper` | 从 PDF 中提取文本 | 像「复制粘贴」 |
| `PDFRenderer` | 将 PDF 页面渲染为图片 | 像「截图」 |
| `PDType0Font` | PDF 中的字体（尤其是中日韩字体） | 字体文件加载器 |

### 1.3 常用操作

#### 读取 PDF 并提取文本

```java
// 1. 加载 PDF 文档
try (PDDocument document = PDDocument.load(inputStream)) {

    // 2. 创建文本提取器
    PDFTextStripper stripper = new PDFTextStripper();

    // 3. 可选配置：按阅读顺序而不是位置排序
    stripper.setSortByPosition(true);

    // 4. 可选：指定提取哪几页
    stripper.setStartPage(1);
    stripper.setEndPage(3);

    // 5. 提取全部文本
    String text = stripper.getText(document);

    System.out.println(text);
}
```

**关键点**：`PDDocument` 实现了 `Closeable`，一定要用 try-with-resource 确保关闭。PDF 文件在读取时会加锁，不关闭会导致后续操作失败。

#### PDF 页面渲染为图片

```java
try (PDDocument document = PDDocument.load(inputStream)) {

    PDFRenderer renderer = new PDFRenderer(document);

    // 渲染第 0 页（页码从 0 开始），150 DPI
    // DPI 越高图片越清晰，文件也越大
    BufferedImage image = renderer.renderImageWithDPI(0, 150);

    // 保存为 PNG
    ImageIO.write(image, "png", new File("page_0.png"));
}
```

**DPI 参照表**：

| DPI | 用途 | 一份 A4 像素 |
|-----|------|-------------|
| 72 | 屏幕预览 | 595 × 842 |
| 150 | 清晰阅读（推荐） | 1240 × 1754 |
| 300 | 印刷级 | 2480 × 3508 |

> **踩坑**：`renderImage()`（无 DPI 参数）默认 72 DPI，文字会模糊。**永远用 `renderImageWithDPI()`**。

#### 创建 PDF 并写入文本

```java
try (PDDocument document = new PDDocument()) {

    // 1. 创建一页 A4 纸
    PDPage page = new PDPage(PDRectangle.A4);
    document.addPage(page);

    // 2. 加载字体（关键！）
    // 方案 A：从 classpath 加载字体文件
    // 需要将 SimSun.ttf 放到 resources/fonts/ 目录
    PDType0Font font = PDType0Font.load(document,
        getClass().getResourceAsStream("/fonts/SimSun.ttf"));

    // 方案 B：从系统路径加载（Linux 上安装 wqy 字体）
    // PDType0Font font = PDType0Font.load(document,
    //     new File("/usr/share/fonts/truetype/wqy/wqy-zenhei.ttc"));

    // 3. 创建内容流（像拿一支笔）
    try (PDPageContentStream contentStream =
             new PDPageContentStream(document, page)) {

        // 开始书写
        contentStream.beginText();

        // 设置行距
        contentStream.setLeading(16f);

        // 设置字体和字号
        contentStream.setFont(font, 12);

        // 设置起始坐标（PDF 坐标原点在左下角）
        contentStream.newLineAtOffset(50, 750);

        // 写一行文字
        contentStream.showText("Hello, PDF!");
        contentStream.newLine();           // 换行

        contentStream.showText("第二行文字");
        contentStream.newLine();

        // 结束书写
        contentStream.endText();
    }

    // 4. 保存
    document.save(new File("output.pdf"));
}
```

**PDF 坐标系统**：PDF 与其他绘图系统不同，**(0, 0) 在左下角**，X 向右增加，Y 向上增加。A4 纸尺寸是 595 × 842 点（point）。

### 1.4 踩坑汇总

| 问题 | 原因 | 解决 |
|------|------|------|
| PDF 中文显示为方框 | 没加载中文字体 | 必须用 `PDType0Font.load()` 加载中文字体 |
| 字体文件找不到 | 路径不对或没有字体文件 | classpath 或系统安装字体 |
| PDF 提取的文本乱码 | PDF 不是标准编码 | `setSortByPosition(true)` 改善 |
| 渲染图片太慢 | DPI 太高或页数太多 | 150 DPI 足够，只渲染第一页 |
| `IOException: Bad file descriptor` | 资源没关闭 | 用 try-with-resource |

## 二、Apache POI — Word 处理

### 2.1 是什么

Apache POI 是 Java 读写 Microsoft Office 格式的库。我们用的是 **POI-OOXML** 模块，专门处理 Office 2007+ 的 `.docx` / `.xlsx` / `.pptx` 格式。

### 2.2 核心类

| 类名 | 作用 |
|------|------|
| `XWPFDocument` | 代表一个 `.docx` 文档 |
| `XWPFParagraph` | 代表文档中的一个段落 |
| `XWPFRun` | 代表段落中具有相同样式的一段文本 |
| `XWPFTable` | 代表 Word 表格 |
| `XWPFTableRow` / `XWPFTableCell` | 表格的行和单元格 |

`XWPF` 前缀 = XML Word Processor Format

### 2.3 常用操作

#### 读取 DOCX 并提取文本

```java
// 1. 加载文档
try (XWPFDocument document = new XWPFDocument(inputStream)) {

    // 2. 遍历段落
    for (XWPFParagraph paragraph : document.getParagraphs()) {
        String text = paragraph.getText().trim();
        if (!text.isEmpty()) {
            System.out.println(text);
        }
    }

    // 3. 可选：遍历表格
    for (XWPFTable table : document.getTables()) {
        for (XWPFTableRow row : table.getRows()) {
            for (XWPFTableCell cell : row.getTableCells()) {
                System.out.print(cell.getText() + "\t");
            }
            System.out.println();
        }
    }
}
```

#### 创建 DOCX 并写入内容

```java
try (XWPFDocument document = new XWPFDocument()) {

    // 1. 创建一个段落
    XWPFParagraph paragraph = document.createParagraph();

    // 2. 设置段落对齐
    paragraph.setAlignment(ParagraphAlignment.CENTER);

    // 3. 创建文本运行（可以理解为一个「文本片段」）
    XWPFRun run = paragraph.createRun();
    run.setText("这是标题");
    run.setBold(true);              // 加粗
    run.setFontSize(18);            // 字号
    run.setFontFamily("微软雅黑");   // 字体
    run.setColor("FF0000");         // 颜色（红色）

    // 4. 再创建一个普通段落
    XWPFParagraph para2 = document.createParagraph();
    XWPFRun run2 = para2.createRun();
    run2.setText("这是正文内容");
    run2.setFontSize(11);
    run2.setFontFamily("宋体");

    // 5. 输出
    document.write(outputStream);
}
```

**段落 vs Run 的关系**：一个段落可以有多个 Run。比如一句话中「这是**重点**内容」——「这是」「重点」「内容」就是三个 Run，中间那个加粗。一个 Run 内部的样式是一致的。

#### 判断标题层级

```java
// 读取 DOCX 时判断段落是什么样式
for (XWPFParagraph paragraph : document.getParagraphs()) {
    String style = paragraph.getStyle();
    // style 可能是 "Heading1", "Title", "Normal" 等
    // 也可能是 null

    if ("Heading1".equals(style)) {
        System.out.println("# " + paragraph.getText());
    } else if ("Heading2".equals(style)) {
        System.out.println("## " + paragraph.getText());
    } else {
        System.out.println(paragraph.getText());
    }
}
```

**Word 中标题的样式命名规则**：英文版 Word 叫 `Heading1`、`Heading2`……；中文版可能叫 `标题 1`、`标题 2`。所以我们在代码中兼容了两种命名：

```java
if (style.matches("(?i)heading\\s*\\d|标题\\s*\\d")) {
    // 提取数字作为标题级别
}
```

### 2.4 踩坑汇总

| 问题 | 原因 | 解决 |
|------|------|------|
| `.doc` 文件打不开 | POI-OOXML 只支持 `.docx` | `.doc` 需要 `poi-scratchpad` 模块，或用 LibreOffice 转 |
| 中文乱码 | 编码问题 | POI 内部用 Unicode，一般不会乱码，检查读取流的编码 |
| `getText()` 返回空字符串 | 内容可能放在表格里 | 加 `getTables()` 遍历 |
| 样式名不一致 | 中英文 Word 命名不同 | 用正则匹配两种格式 |
| `The package should be closed` | 未关闭资源 | 用 try-with-resource |

## 三、Thumbnailator — 图片处理

### 3.1 是什么

Thumbnailator 是一个轻量级 Java 图片处理库，专门用来做图片的缩放、裁剪、格式转换、加水印等操作。相比 Java 原生的 `ImageIO` + `Graphics2D`，它的 API 优雅非常多。

### 3.2 核心 API

一切从 `Thumbnails.of()` 开始，这是一个流式 API（方法链）：

```
Thumbnails.of(输入图片)
    .size(宽, 高)      // 指定尺寸
    .scale(比例)        // 或者按比例缩
    .outputFormat("png") // 目标格式
    .outputQuality(0.9)  // 质量（0-1，仅 JPEG/WebP 有效）
    .toFile(输出文件)     // 输出
    .toOutputStream(流)  // 或输出到流
    .asBufferedImage()   // 或输出为 BufferedImage
```

### 3.3 常用操作

#### 图片格式转换（最简单）

```java
// 把 PNG 转成 JPG，缩放到 800x600，质量 90%
Thumbnails.of(new File("input.png"))
        .size(800, 600)
        .outputFormat("jpg")
        .outputQuality(0.9)
        .toFile(new File("output.jpg"));
```

#### 仅格式转换，不缩放

```java
// scale(1.0) 表示保持原尺寸
Thumbnails.of(inputStream)
        .scale(1.0)
        .outputFormat("webp")
        .outputQuality(0.85)
        .toOutputStream(outputStream);
```

#### 按比例缩放

```java
// 按比例缩放 0.5 倍（即缩小一半）
BufferedImage thumbnail = Thumbnails.of(image)
        .scale(0.5)
        .asBufferedImage();

// 或者指定最大宽高（保持宽高比）
BufferedImage resized = Thumbnails.of(image)
        .size(200, 200)   // 200x200 区域，保持比例
        .keepAspectRatio(true)
        .asBufferedImage();
```

#### 图片旋转和水印

```java
Thumbnails.of(image)
        .size(400, 400)
        .rotate(90)                    // 旋转 90 度
        .watermark(Positions.BOTTOM_RIGHT, watermarkImage, 0.5f) // 右下角水印，半透明
        .toFile("output.jpg");
```

### 3.4 踩坑汇总

| 问题 | 原因 | 解决 |
|------|------|------|
| JPEG 输出颜色异常 | PNG 有透明通道，JPEG 不支持 | 先转 RGB 再写 JPEG（PDFBox 也一样） |
| `outputQuality` 对 PNG 无效 | PNG 是无损格式，quality 参数只有 JPEG/WebP 有效 | 忽略即可 |
| 图片方向不对 | 手机拍照的 EXIF 方向信息 | Thumbnailator 不处理 EXIF，需额外处理 |
| 大图片 OOM | 原图太大 | 限制上传文件大小，先 `scale()` 缩小 |
| GIF 只取第一帧 | Thumbnailator 不支持动图 | 动图处理需额外的库 |

## 四、flexmark — Markdown 处理

### 4.1 是什么

flexmark 是 Java 上功能最全的 Markdown 解析器，支持 CommonMark 标准和 GitHub Flavored Markdown（GFM），包括表格、删除线、自动链接等扩展。

### 4.2 核心 API

```java
// 1. 创建配置（设置扩展）
MutableDataSet options = new MutableDataSet();
options.set(Parser.EXTENSIONS, Arrays.asList(
        TablesExtension.create(),            // 表格支持
        StrikethroughExtension.create(),     // ~~删除线~~ 
        AutolinkExtension.create()           // 自动链接
));

// 2. 创建解析器和渲染器
Parser parser = Parser.builder(options).build();
HtmlRenderer renderer = HtmlRenderer.builder(options).build();

// 3. 解析 Markdown → AST（抽象语法树）
Document document = parser.parse("# Hello\n**World**");

// 4. 渲染 AST → HTML
String html = renderer.render(document);
// 输出: <h1>Hello</h1><p><strong>World</strong></p>
```

### 4.3 HTML → Markdown 反向转换

flexmark 也支持反向转换：

```java
String md = FlexmarkHtmlConverter.builder(new MutableDataSet())
        .build()
        .convert("<h1>Hello</h1>");
// 输出: Hello\n======
```

### 4.4 踩坑汇总

| 问题 | 原因 | 解决 |
|------|------|------|
| 表格渲染不对 | 没加 `TablesExtension` | 创建 Parser 时配置 EXTENSIONS |
| 行内 HTML 被转义 | 安全模式 | 默认不转义，是正常行为 |
| 中文换行异常 | Markdown 的换行规则 | 配置 `HtmlRenderer.SOFT_BREAK` |

## 五、总结：什么时候用哪个库

| 要做什么 | 用哪个库 | 注意事项 |
|---------|---------|---------|
| 从 PDF 提取文字 | PDFBox `PDFTextStripper` | `setSortByPosition(true)` |
| PDF 转图片 | PDFBox `PDFRenderer` | `renderImageWithDPI()` 不要用 `renderImage()` |
| PDF 转 Word | PDFBox 提取文本 + POI 写 DOCX | 失去格式排版 |
| 读 Word (.docx) | POI `XWPFDocument` | 注意遍历表格 |
| 写 Word (.docx) | POI `XWPFDocument` + `XWPFRun` | Run 是最小样式单元 |
| Word 转 Markdown | POI 读 + 自己拼 Markdown 语法 | 处理标题和列表样式 |
| 图片转格式 | Thumbnailator | `scale(1.0)` 不缩放仅转格式 |
| 图片缩放 | Thumbnailator `size()` / `scale()` | `keepAspectRatio(true)` 保持比例 |
| Markdown 转 HTML | flexmark `Parser` + `HtmlRenderer` | 加 `TablesExtension` |
| HTML 转 Markdown | flexmark `FlexmarkHtmlConverter` | 简单场景够用 |
| 创建 PDF | PDFBox `PDPageContentStream` | **务必加载中文字体** |

### 核心原则

> **PDFBox 最坑的是字体，POI 最坑的是样式名，Thumbnailator 基本没坑，flexmark 最坑的是忘了加 Extension。**

最开始写的时候，**每一类转换先写一个单元测试**验证通了，再集成到业务代码中。PDF 中文渲染的问题尤其要在开发环境提前验证好。
